# D05 普通偏好自述：人工候选与审阅

实施依据：`D05_EXPLICIT_PREFERENCES_DESIGN.md`（设计提交
`a0c77e371f13e0843dc41cf13205f6a69d72f19d` 已获限定独审 ACK）。
本文件描述当前实现，最终验收须查对应完整 SHA 的实际报告；实现尚待独审，不能据设计 ACK 称完成验收。

原文详情的“普通偏好自述”由用户逐字填入原文唯一片段，选择或新建普通主题，明确确认本人普通偏好自述后，
只创建待确认候选。另一次比较确认才采纳；有同主题已采纳项时展示双方，明确选择取代，不按时间自动覆盖。
回忆的独立入口可浏览待确认与用户已采纳自述，查回原文 code-point 高亮。纠正产生新的待确认内容版本；
撤回有独立预览、取消、确认。未知有效区间一直保留“未说明”，不从记录或操作时间推断。
这是用户人工分类，不能识别所有敏感内容、转述、假设或错误归类，不证明陈述真实或永久成立。

内容版本和审阅检查点分离，每行至多8内容版本；每版本独立 predecessor/successor 两槽。
A→B→C 保留 B 的两个不同操作端点。纠正 B1→B2 不把 B1 端点搬到 B2；撤回或删除不复活旧采纳。
profile3 专用 API、AES-GCM 子密钥用途/AAD/明文格式，与摘录 profile1、事件/情绪 profile2 隔离。
同一 records owner/SQL actor 认证来源版本、hash、generation、政策、捕获元数据和删除证明；
真实 SQL 事务双行 CAS、读回和同请求摘要使失败回滚、丢回执可核对。来源改变清密文，不靠禁用按钮维持权限。
界面导航/锁/暂停/owner退休使旧 session 和确认失效；不写入 SavedState。

单来源20、全库128 READY、所有候选物理行4096、READY密文总量4MiB，读取先有界，超限拒绝。
每份密文最大32797B；正文只按当前来源逐条认证，不同时缓存全库128份正文。

完整资料库备份 v10 承载 profile3（包括失效行）及双向历史关系；恢复前逐边认证，拒绝仍可解析但错配的端点。
缺失/失效目标仅为不可解析历史，不能恢复其正文或旧请求权限。v10沿用v9音频描述段和原13表布局；
v8/v9读取保留，选定记录包的v9音频/日期包装不变。恢复重加密到新owner并归一LOCAL_ONLY，不恢复联网授权。
选定记录包或手工文本导出不包含普通偏好；UI明确完整资料库备份范围。
