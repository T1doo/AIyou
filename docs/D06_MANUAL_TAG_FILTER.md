# D06 统一五类找回：人工标签筛选设计候选

基线 `804a6d797d67fc76a378c6b0ff9d19327cd7b447`；仅设计，运行代码／两份原方案未改。
遵循原方案 §5.2、§10.3–10.4；只扩人工标签筛选，不并人物、别名、语义、AI标签或任务。

## 1. 已核事实与先审的身份边界

现有 `ManualTagSnapshot.names` 是每原件独立版本的规范标签名称数组；
`entry_manual_tags(entryId,version,lastMutationId,ciphertext)` 没有 tagId／全局标签实体。
现有 `LocalSearchRequest.tag` 按规范名称做原文交集；AES-GCM／AAD绑定记录、版本和mutation，
标签 INSERT/UPDATE/DELETE 已推进 `local_search_epoch`。不把数组下标、每次随机UUID当稳定ID。

本片推荐**库内标签值 ID**：对当前加密库密钥派生独立用途子密钥，HMAC-SHA256 计算规范名称的
不透明ID；字段用版本前缀／长度编码，密钥用途与既有标签加密分开。使用已有JCA和随机库密钥，
无新SDK／Android alias／凭据，子密钥同owner排空后擦除。ID、名称、查询都不写日志／Bundle。
固定派生info为 `AIyou/manual-tag-selector/key/1`、输出32字节；ID输入依次是
`AIyou/manual-tag-selector/value/1` 与规范名的长度前缀UTF-8，输出完整256位小写hex，不截短。
同规范值在同库密钥下跨读取、分页、冷启稳定；不同大小写、内部空白、组合字符继续按旧规则区分。
保留已有外侧Unicode空白规范化、每原件12项／每值40码点和失败不等于空集合的合同。
每个选择票据另绑实际owner，不能仅凭ID跨库／跨已退休owner复用；选择不接受任意调用者伪造的名字。

**独审必须明确接受此稳定性范围，才能实施。** 这是新增的值身份提议，不是已有持久tagId：
现有标签编辑是移除／新增值，改值产生新ID；完整备份换目标库密钥后ID可变，查询票据本来就不恢复。
本片不承诺跨改名、跨密钥迁移的实体身份。若“稳定标签ID”必须包含这两项，则此方案不够，
需先另审持久加密标签目录、成员ID格式／迁移、删除传播及全部备份恢复路线；不能偷偷扩schema，
也不能只增加一个ID字段却留旧恢复路径丢身份。该前置尚未获实施许可，本轮不实现任一方案。

## 2. 一个显式交集入口

在统一找回既有“筛选条件”卡片内增加“选择人工标签／不限标签”、单选当前已认证标签和清除。
保持现有Lazy分段：0关键词／类型，1筛选，2动作／状态，3起结果；不再因加控件移动所有旧测试定位。
选择器由用户主动打开才读取标签；初始和空白关键词仍不自动展示原件。文案明确“按所属原件的人工标签筛选”。
请求为关键词 AND 捕获日期范围 AND 可选人工标签值ID；类型范围照旧。没有标签条件沿用当前行为。
标签名字不替代关键词，不扩大原文或派生文字的逐字命中，也不产生新的原文高亮位置。
同一原件的五类证据共用其当前人工标签资格；证据 O/A/I/P/M 身份、去重、排序、20组分页不改。

## 3. 有界选择器与认证票据

选择器只列当前可见原件的人工标签，按既有政策保留允许读取的手工标签，不混入派生标签。
回收站／任意永久删除阶段来源不入选择器；手工标签的AI_NONE规则不因选择器而放宽或收紧。
图／音单独记录的正文可空，认证不能误用要求正文非空的SourceMemoryPreview。
沿同一加密records owner，以id keyset每批20条轻量metadata扫描，按现有cipher长度上限预检再加载单行；
逐行认证标签AEAD、规范值、版本／mutation及实际当前原件hash／修订／generation／捕获元数据。
同值在多原件中只列一个选项；名称排序用固定Unicode码点序，ID作稳定附键，不随手机locale变化。
每页全量扫描后仅保留至多21个去重后的最小候选（top-K／游标），不调用现有无界snapshots()拼全库字典。
保留单原件12个标签／单行正文和21个选项，滚动回执覆盖完整合格标签集合／源元数据／全局epoch，
不新增全库128／1000的标签数量或保存上限。当前页或所选ID若对应不同规范值，整组拒绝，不悄悄合并。
空集合须完整认证和提交ACK后才显示；损坏、范围过大或读取失败有独立错误，不能冒充“暂无标签”。
翻页／选中再验完整集合及私有owner票据；旧页、外部ID或迟到回调不能选入新会话。

## 4. 预算前筛选与最终共同事务

选中票据含值ID、认证显示名、owner及集合证明；完整请求／私有proof绑定关键词、类型、日期和选择。
新API在旧端口不支持标签条件时明确失败，不能丢弃条件转成不限标签。返回结果须与提交的筛选一致。
实际data owner验证ID／规范值／票据，不以UI传来的名字或任意记录ID列表作为授权或完整集合证明。

- 原文：data层从已认证ID解析规范值，传入现有 `LocalSearchRequest.tag`；保留日期、真实标签认证，
  在正文与1000候选预算前取交集。既有10000扫描、FTS超集、正文逐字核验和所有预算不变。
- 原音文字／图片文字／普通偏好：保留完整媒体／集合／图认证及128等既有容量；再认证所属原件标签取交集。
- profile2：完整认证所有合格行的历史／来源和当前所属标签，包含标签外、日期外、未匹配及未采纳行；
  只有当前ACCEPTED、字段逐字匹配、日期和标签都符合才累加1000命中预算并保留当前投影。
  标签外1001个命中不能挤掉标签内唯一结果；标签内1001仍整组失败，不截断或限制保存。
- 最后共同SQL事务再次认证完整标签集合／epoch、各类型集合及真实来源，核成员和请求，提交ACK后才发布。
  无标签行的版本0空集合也受全局epoch保护，覆盖空→非空／标签移除再加回／非命中来源变化。
  名字或密文损坏不当成“不匹配”。日期／标签外的合格数据继续遵守原完整认证边界，不能靠筛选跳损坏。

仍为流式线性扫描加有界top-K；HMAC／标签解密在数据层，每原件最多12值，不进UI逐行guard。
不承诺设备时延或与全库大小无关的性能；必要验证用计数证明无全量Map／旧bindings重复哈希。

## 5. 来源退休、返回与编辑

有标签条件时，所有scope观察到 manualTags 版本／名称／可用性／错误、所属原件、政策、删除、
generation或owner变化均退休完整查询／选择器／returnSeed，包括非命中来源；不限标签保留原有策略。
不要直接按ManualTagSnapshot对象引用比较相等；用版本／规范值和owner的真实语义变化。
实际VM update在CAS内只清对应旧内容，CAS外按观测session/request/lifetime退休，不伤新会话。
UI已清空的导航交接期间仍保留私有“有标签条件”标志；O(1)当前请求门不遍历标签或entries。
实际SQL取消释放才算资源ACK；保留 navigation→lifecycle 锁序、私有admit和提交确认规则。

选择／清除标签推进request、清旧proof和内容、回第一页，不自动查询；关键词／日期编辑不改标签值身份。
人工标签编辑的真实准入应先退休统一查询和seed，不只隐藏Dialog；原有标签版本CAS／幂等写入不改。
正常返回携带owner范围内的值ID和已认证预期名称，重新认证选择与当前集合、重新查第一页，绝不恢复旧proof。
所选值已不可用则清内容并提示重选／不限标签，不能静默回退为未过滤查询。观察到变化或后台／恢复则清私有状态。
原文／原音／原图精确回跳、QUOTE／NOTE定位与所有处理许可不改；不自动播放、提取、推断或创建任务。
