# §5.5 / §14.1：以后新草稿的默认处理范围

从已签收的 `02abc4120cf860bdec4c5dc1f9c9f51250346e8c` 接续。设置 → 本机与隐私
新增“以后新草稿的默认处理范围”，可明确选择“仅本机处理”或“不参与 AI”。新安装、
不存在的设置文件以及原 v1/v2 偏好均保留 `LOCAL_ONLY` 默认。没有远端选项或发送能力。

## 生效范围

复用同一设备偏好文件与 AtomicFile 写入／读回，v3 增加一个受限枚举。原 v1/v2
读取不重写字节，显示／动效／回顾偏好保持。默认范围不是记录、外发授权或凭据，
不进入完整资料库备份；恢复不改变本机的全局默认。

生产开库接线把实时只读 provider 交给原加密记录 owner。只有 `CAPTURE_CURRENT`
和 legacy 文字草稿均不存在、确实新建槽时才读取它。当前草稿即使为空也保留自己的
范围、身份和版本；已有记录、legacy 迁入、恢复包带入的草稿均不补写或跟随默认。
保存或明确清空之后的新草稿采用当时落盘的默认。逐稿范围选择仍独立，不回写默认。

同文件读写及写后读回共用静态锁，防 AtomicFile 读取恢复 `.bak` 干扰写入。
该锁内没有 SQL／UI 回调。设置写入返回异常可能已落盘，界面明确显示“尚未确认”，
保留同一待确认值，禁止另起设置，重试只核对同一次设置，不回滚文件或当前草稿。

未知或不可读取的设置原字节保留；只对 `IOException`／`SecurityException`，以后新建
的草稿暂用更严格的 `AI_NONE`，仍可本机记录并逐稿选择。当前草稿不因此改变。
设置和此刻的失败提示反映偏好 VM 的读取状态，不能声称覆盖每次 provider 的运行期
降级；本次实际范围始终由草稿中的选择展示。没有新增重置、授权、缓存或处理框架。

空库恢复仅兼容未编辑的 version1 空白 `AI_NONE` 初始化槽，与原 `LOCAL_ONLY` 槽相同。
手动改过范围／版本、非空输入、图片、终态或未知行仍不满足空库条件。新增一项交互
测试覆盖该兼容点，没有手工重跑此前完整备份矩阵。
