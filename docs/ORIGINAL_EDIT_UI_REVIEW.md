# D02 原文编辑切片：待新源码与 CI 独审

原方案 F02、5.4 要求原始记录的编辑版本，8.2 要求旧响应不能覆盖新状态。此前 f751f429 的原文阅读已由父侧独立审阅通过；本次接通现有加密仓库 `revise(entryId, expectedRevision, text, createdAt)` 到真实 App/ViewModel，形成阅读、编辑、保存新版本或取消的本地闭环。

编辑页由稳定 ID 与当前版本开启，显示基于哪个版本、保存保留旧原文、仅本机的说明。未修改 Room schema、迁移、锁文件、SDK、依赖、网络或 AI；使用现有版本事务及新版本本地索引作业。没有分析模块，不假称旧分析已更新或 AI 已执行。

编辑输入与“此刻”加密草稿分开。编辑状态保存在 ViewModel 内存，配置变化时沿用；不把原文或修改放入 Bundle、rememberSaveable、SavedStateHandle、日志、明文文件或 capture_draft。未保存修改尚不支持进程终止恢复，界面说明其仅在当前应用会话保留；正式原文与此刻的持久化草稿仍保留。完整 D02 的设备重启/迁移门槛未因此关闭。

保存以当前编辑会话、预期源版本和完整输入快照提交，空白/未变化不提交，超过 100000 UTF16 的替换被拒绝并保留上次完整输入。保存中禁止重复保存、覆盖输入和取消；Back 被消费，不能把取消显示成持久化事务已经撤回。成功只在事务返回并读取数据库记录确认后显示，再返回同一原文阅读页；两列表位置与选中 ID 沿用原有导航。

写入失败保留修改及旧原文，允许用户纠正后重试。事务已返回但列表读取失败，进入只读待确认状态，重试只读回，不再次调用 revise。源版本变化或记录消失时，刷新当前原文列表并保留用户正在编辑的文本，拒绝覆盖当前版本或另造记录；可选择复制自己的修改，明确取消后重新打开最新原文。没有自动合并或自动放弃输入。

进入编辑前排队的此刻草稿若稍后写入失败，编辑页提供本机存储重试；同一 IO 队列重新保存当前此刻草稿并读回记录，保留原文编辑会话、输入、预期版本。恢复失败仍保留两份输入，不要求放弃修改。恢复成功后可继续保存原文新版本；没有将编辑输入写进此刻草稿。保存中和待确认时，顶栏与正文的取消控件均真正禁用。

取消未变化输入立即回到阅读；有未保存修改则通过 App 取消操作、系统 Back 显示“继续编辑／放弃修改”确认。会话 ID 加现有导航 generation/dispose 门禁，使旧打开、输入、保存、取消、放弃回调不能作用于关闭后重开的同一 ID 或已卸载界面。原文阅读进入编辑会使此前阅读复制会话失效。

## 新增实际检查

八项主机测试编译真实生产 ViewModel/编辑状态源，通过受控仓库边界验证新版本保留、捕获草稿未消费、提交与读回失败、版本变化/删除、重复操作、输入边界和旧会话。主机仓库是合成 IO 边界，不是 Room/SQLCipher/Keystore 验收。

十项 Compose/JVM 用例连接真实 App、真实 ViewModel 与注入的领域仓库，使用真实控件点击、输入、滚动和 Back。涵盖读改存回到新原文及列表锚点、取消确认、提交迟到操作、失败后用户纠正、源变化/删除、已提交只重试读取、同 ID 重开/dispose、320×640dp/200% 字体和完整输入边界。中段记录保留精确滚动语义值与选中断言，另以真实末端场景核对更新正文、选中、完整可见几何与底部边界；末端视口或项尺寸变化时允许 Compose 正常回滚，不将无障碍伪偏移当成累计像素。保留原 23 项 App 用例与原文密集末端验证；新的守卫要求至少 33 App、14 queue，且 22 个具名 App 用例真实存在并通过。
