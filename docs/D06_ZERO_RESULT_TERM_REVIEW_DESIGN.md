  SideEffect 会自动 `search.sync`，直接删字不是“先审阅、确认后才查”。
- `LocalOriginalSearchSection.kt:175` 的“清空查找条件”会在
  `MainActivity.clearSearch` 同时清掉关键词、日期、标签、人物、收藏与图片。
- `QuestionKeywordScreen` 已支持问题原字选词、编辑和明确日期后确认，但入口
  不带入当前零结果查询；它不是仅删减本次既有词的流程，不应复制提词算法。
- `LocalRecordsScreen.kt:397–402` 的零结果提示只有“试试更短的关键词或调整日期”，
  没有保留条件、选词移除及确认前预览。因此最小差异是零结果旁一个动作，
  复用现有助手的仲裁和模态阻止自动查询能力，增加独立的“删词审阅”分支。

v3 的 q09 两路含“梯子”，原文是“折叠梯”；q03 含“标记”，原文写“贴上设备名”。
它们证明词法缺候选，不能证明自动删掉哪词正确。此流程只让用户自己决定；
不将这些题预写成推荐删词，不补查本集后声称提升。24题已转固定回归，后续效果
需要新题族；功能验收另用新合成夹具，不借 v3 gold 选词。

## 一个入口与一次确认

1. 仅当前本机原文 `KEYWORDS`、已确认发布的 `READY + hits为空` 展示“删减关键词再查找”。
   精确片段、加载、失败、无效、仅筛选/浏览不是该入口。当前实际可见 state、
   owner、输入和导航必须一致；没有索引 owner/private proof 不进入此分支。
2. 对新增入口先做廉价 UTF-16 长度检查（≤128）再校验 Unicode/码点数（≤64），
   按现有 matcher 的 Java whitespace/Zs 规则拆出2–8个非空词，词内控制字符不准入。
   只抽出共用纯拆词函数，
   不改变现有匹配规则。超范围或只有1词仍可用原自由编辑入口；不裁切，不给正常
   100000字符输入新增限制。重复词按原位置区分，原顺序/字形保留，不按同文合并。
3. 弹窗标题“删减关键词再查找”，展示完整原查询及各词，默认全部保留；用户点词
   明确移除/恢复。显示剩余词和“全部包含”；不能输入新词、自动推荐删除、选择
   同义词或切成OR。至少保留1词且实际移除过1个词项才可确认；重复词允许保留，
   不套用现有问题提词器的去重限制。确认使用剩余原词按原顺序以空格连接。
4. 完整展示并保留原日期依据、原始from/through、捕获时区/人工事件日期规则，以及
   标签/人物/收藏/图片条件。此页没有日期或其他条件切换；“确认剩余关键词并查找”
   明确提示删词可能扩大匹配范围，但日期等条件不变。不推断用户问的是发生日期。
5. 打开/切换词项只改内存草稿，零新查询、零规范输入写入；确认后才一次原子提交
   query+同一完整条件，再走既有生产查找/认证/排序/精确出处路径。零结果也照实显示，
   不继续自动删词或清空条件。一个词都未删、全删、旧回调、双击均须actor拒绝。
6. 取消不提交删词，保留旧规范输入、不恢复旧 proof。与现有助手保持一致：关闭后
   SideEffect若重查，只能以完整旧条件取得新 proof，不是隐式提交删减草稿。
   后台、退出、导航/owner/来源变更、重建、dispose清掉草稿；不存 Bundle/Saver/日志。

## 复用现有门，补齐零结果准入

- 在 `QuestionKeywordController` 同一私有仲裁/serial/lease中增加typed reduction草稿，
  沿用单一非空 `state` 作为阻止自动查找标记。不另建会互相抢锁的控制器或全局框架。
  原问题分支保留；reduction不伪造“完整问题”，单独生产展示体。
- reduction仅接受自身的词项切换/确认/取消。原question/terms/choose/日期等旧入口
  在此模式下actor拒绝，不能只靠不显示按钮。一次确认绑定当前UI身份、opaque lease、
  session、问题/词项版本、原输入ownership、完整条件、导航与来源浅绑定；失效清草稿。
- 锁序仍为 `navigation → helper → search`，不在search锁内回调helper/获取navigation；
  确认在同次仲裁中完成规范输入提交与状态关闭，不留UI-null后旧回调提交的窗口。
  原 `questionUi == null` 的compose读法继续覆盖两分支，勿只在稳定SideEffect里读。
- 当前搜索在SQL publication回调里先发READY，`publishCurrent`返回后才得真实commit ACK。
  新入口不能只凭该中间READY。为新入口增加controller私有“已确认结果identity”回执：
  仅publishCurrent成功返回且request/source/input仍当前时记录；失败、取消、输入/来源变化、
  pause/clear/dispose退休。无逐行entries遍历/哈希，原结果发布和排序不为此重构。
  点击准入在上述锁序内核该回执和真实空state；ACK未到显示“结果仍在确认，请稍后再试”，
  不开草稿/不更改输入/不查询。提交失败或ACK丢失不得取得零结果准入。
- 成功开草稿后立即用原retireSearch清掉旧结果、出处、return anchor与proof引用；
  不将旧SQL proof转成删词权限。保留的是内存输入/owner/来源版本绑定，确认须重新查。
  VM已观察的来源/元数据非命中变化及输入ABA、生命周期退休都使草稿失效；
  外部存储先变而VM尚未观察时，不承诺即时感知，最终新查询仍由生产
  仓库认证全部当前范围、publish确认后才可用，原文回跳继续实际resolve版本/owner核验。
