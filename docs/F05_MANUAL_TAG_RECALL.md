# F05 / D06：当前手工标签附加召回

落实原 Master Plan §10.4 与产品架构同章的用户确认标签附加召回。原始方案不改。
普通关键词的每个词可在当前原文或当前手工标签中逐字满足，沿用大小写折叠规则；
精确片段仍只匹配当前原文。标签仍需由用户明确保存，模型推测不成为检索标签。

FTS4 复用现有 bodyTokens、tagTokens 和同一加密数据库，不改词元格式、profile、
schema 或依赖。查询仅使用应用生成的编码词元，在两个文本列中召回候选；单字、
标点、精确片段及未知/待更新索引继续走已有有界回退。最终 matcher 在认证后的
原文或单个手工标签内核对完整字面词，拒绝跨标签拼接的 n-gram 假命中。

结果显示“手工标签命中”。需要标签才能满足全部关键词的结果，只显示真实原文
开头片段，不设置正文高亮/定位范围，不构造原文引用，也不进入本机 AI 出处候选。
实际正文满足全部关键词时保留原有高亮、code-point 引用和排序规则。日期、人物、
精确标签、收藏和当前版本图片筛选仍取交集；普通人工查找仍可查看 AI_NONE。

标签快照身份参与关键词结果的当前所有权检查。索引 publication/resolve 沿用同一
SQL owner、私有 proof、标签版本和全局 epoch 校验；修改/移除、删除/恢复、来源
修订、页面退出或替换 owner 后，旧结果与迟到回调不能重新发布或打开。

本片不启用模型、后台、权限或网络，不增加明文缓存。实际测试及失败记录以本片
精确 SHA 交付回执为准；主机 SQLite/Compose 与原生测试编译均不是设备执行。
原 D04 生产发送、原生 Keystore、真实设备与完整 D06/D09 验收继续保持各自边界。
