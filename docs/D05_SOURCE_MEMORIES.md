# D05 事件与当次情绪的人工审阅

本片对应两份原方案 §8、§10.1–10.2：手选当前原文中的逐字片段 → 人工选择事件／当次情绪及自述／上下文／含义未确认 → 独立确认保存待审候选 → 逐项采纳或拒绝 → 撤回、纠正及重新打开。这里没有自动结构化抽取、真实模型或语义支持判断；完整 D05 仍 OPEN。

## 产品含义

详情页“事件与当次情绪”是实际入口。默认是“含义未确认”，没有关键词分类器。用户可修改最多320个 code points 的原文摘录，须在当前原文中逐字且唯一匹配；不处理草稿、问题聊天或旧版本。人工备注可空、最多200个 code points，明确与原文证据区分。事件／情绪是用户分类，采纳仅保存人工审阅结果，不证明事件实际发生，不建立稳定偏好、人格、关系或诊断，也不创建任务或系统提醒。

原始捕获时间及 IANA 时区保留为来源元数据；没有推断事件发生时间，也没有把“昨天”等相对时间重解释为执行日期。否定、引用、假设、未完成计划逐字保留，不自动转成肯定事实。

保存待审与采纳是两次独立确认。待审可采纳或拒绝；已采纳可撤回；已拒绝或撤回可明确重新待审。纠正可改摘录、类型、分类或人工备注，必须有真实内容变化：旧内容保留为 SUPERSEDED 及其原审阅状态，新内容版本始终 PROPOSED，需要再次单独采纳。最多8个内容版本；普通审阅 CAS 不消耗内容版本，达到内容上限仍可拒绝或撤回。历史保留内容取代链和当前审阅，不宣称是每次点击的完整审计日志。

每个当前原文版本最多20条有效候选，失效条目不能挤掉有效条目。新建是用户发起的独立候选，不承诺语义去重。编辑原文后旧候选失效，当前原文列表不混入旧版本内容；处理范围／来源代次变化导致失效后不能通过重新待审复活。

## 集中待审入口

回忆页“待审事件与情绪”汇集现有人工候选，按候选建立时间降序／ID升序分页。
每页认证最多20条当前可用的人工候选，只展示当前内容版本为 PROPOSED 的条目；
已采纳等条目不混入待审。计数明确为本页，空页仍可能有更早候选，保留前后页与刷新入口。
读取失败不显示假空或部分结果。刷新、关闭、恢复与导航使旧页操作失效，不保存查询页到 Bundle。
来源跳转前在同一 SQL lease 内重新核对整页成员、密文回执与来源，随后打开现有原文和人工审阅界面；
跳转本身只读，不采纳、不重新分类、不新建任务。采纳与纠正继续使用原有独立确认和行版本 CAS。
沿用现有表、密文、密钥用途和排空 owner；不增加权限、协议、依赖或迁移，也不混入旧逐字摘录批次。
三项 Compose 方法覆盖320dp／200%字体、来源跳转后的单独确认、失败与恢复后的旧回调，
以及已采纳浏览、人工备注与撤回后的空列表；
实际执行结果按精确提交的 XML／CI 收据报告，编译不代替原生设备验收。

回忆页另有“找回已采纳事件与情绪”：按同样分页边界浏览当前 ACCEPTED 内容，显示逐字依据、
人工备注、分类和来源捕获时间，可回到现有审阅页纠正或撤回。采纳只表示人工审阅决定，
不证明事情发生；捕获时间不冒充事件时间。切换待审／已采纳会退休旧页操作、从第一页重新读取。
纠正后的新版本重新待审，撤回后的条目退出已采纳视图；旧页不能打开先前已采纳的内容。

## 加密、类型隔离与来源校验

原方案允许多个逻辑模型共享物理表。本片复用 `local_candidate_batches` 的索引、源绑定、失效和删除链；保留 `ruleVersion=1` 为旧摘录格式，明确保留 `ruleVersion=2` 为本片产品格式 discriminator，不能把它当作旧摘录规则升级。新条目物理状态保持 READY，所有业务审阅状态在独立用途密文中；来源失效统一变为 INVALIDATED 并清除密文。两个仓库在 SQL WHERE 中先按类型隔离再限量，按 ID 的旧／新请求都不能跨类型操作。

使用同一排空 SQL owner 及既有数据库 key，以独立 HMAC 用途派生 AES-GCM 子密钥；不新增表、迁移、依赖、Keystore alias 或凭据。AAD 绑定用途／格式、ID、来源 ID/版本/hash/generation、产品格式、行版本、物理状态、完整请求回执摘要及创建时间。密文包含来源捕获时间／时区／政策／创建 epoch、逐字引用、人工分类及备注、连续内容版本／取代链、当前审阅和最后操作合同，严格校验长度、枚举、版本及 EOF。owner 排空后擦除子密钥，旧摘录和人工标签 cipher/API 不变。

创建预览绑定当前来源、捕获元数据、政策和持久全局 epoch，防止来源访问缺行→插入→删除的 ABA。首次创建再次检查 epoch；丢 ACK 后先识别原始 ID 与完整请求精确回执，再检查新建容量，避免第20条成功后重试被拒。已有条目依靠不可变绑定、源失效触发器终态和行 CAS，不因无关记录的全局 epoch 变化自动重写。

每次读取／写入都重新检查来源版本/hash/generation、当前政策、删除标记与任意阶段永久删除收据，并验证全部内容版本的引用。审阅／纠正同时绑定 expected rowVersion、contentRevision、previousReview 及完整请求元组。精确重试返回原密文；更改请求或稍后的审阅／纠正会拒绝旧请求。异常事务全部回滚。回收站立即清除派生内容；恢复默认 AI_NONE，重新授权也不能恢复失效候选。永久删除继续清除该来源所有产品格式的物理行，没有只删除当前类型的过滤。

## 界面、测试与未验范围

表单、引用预览和确认 authority 仅在内存；对话框禁用 SaveableStateRegistry，关闭／恢复／导航使旧 token 和业务闭包失效。未知保存状态隐藏未经核对的结果，不显示假成功或假空列表；当前会话保留同一不可变请求用于核对。未保存表单关闭后清除，已保存候选及纠正链重新从仓库读取。引用可回到原文并高亮 code-point 范围；操作滚动可达且至少48dp，窄屏200%字体以实际 Compose 门禁核查，不能代替 TalkBack 真机测试。

Host覆盖真实领域、SQLite 事务、JCA AEAD、独立连接、ViewModel IO actor、保存冷重开、旧类型混存、回收站与实际永久删除链。Compose使用生产路由／controller及受控持久回执端口，不冒充 SQLCipher。既有原生 Room/SQLCipher 方法追加迁移后创建／采纳／纠正／重开断言；编译及 DEX 清单不等于设备运行。

最终 SHA、实际 XML／构建／lint／CI 结果及原始失败另附交付收据。保留 SourceTag 初始176/177、24ba本地513/515、49b初始化失败和早期 cancelled CI／ELF RELRO／HTTP失败记录，不用本轮通过覆盖它们。生产重启、Keystore、16KB、TalkBack、OEM及性能验收仍 NOT RUN；完整 D02/D04/D05/D06/D08及完整 D07 系统提醒仍 OPEN。选定记录包／手工开放导出未加入这些候选；已有完整离线资料库 v8 会保留人工记忆与纠正链，详见 [F08 完整离线备份](F08_FULL_OFFLINE_BACKUP.md)，不能将主机恢复验证称为跨设备验收。
