基线 `866f274c8daffe48c162d4bce78b166b67160186`。两份原方案 §5.2 明列收藏筛选；
现有原文入口 `LocalSearchRequest.onlyFavorites` 已实现，统一五类入口尚无此条件。
已按本合同形成运行代码候选，实际证据单独封存；人物筛选、561 字形和当前树原生验收不由此签收。

## 最小用户闭环

- 既有筛选卡片 item 1 内增加单一“仅看所属原件已收藏”复选行，默认关闭，整行至少 48dp，
  有明确选中语义及键盘焦点。状态同时用文字说明，不靠颜色；完整换行，保留 item 0/1/2/3 结构。
- 这是原件级人工收藏：五类证据同用其所属原件的当前收藏资格，不独立收藏派生内容，
  不把收藏当成事实确认、偏好或 AI 授权。原件文本修订后既有收藏身份规则保持，旧版本证据仍失效。
- 关键词 AND 捕获日期 AND 人工标签 AND 人工人物标记 AND 可选收藏，类型范围和证据身份不变。
  切换条件只推进请求、清 proof/结果/旧错误、回第一页，不自动搜索；空白词不扫描全库。
  “清空查询和结果”同时重置收藏条件。关闭条件是用户显式选择，读取失败不得自动转不限收藏。
- 五类原件回跳不改内容、收藏、标签或权限，不自动播放/提取；返回保留条件但必须重新查询第一页。

## 同一加密 owner 的完整证明

- 复用 `SqlRecordFavoriteRepository` 的真实 metadata 解码规则与 SQLCipher entries 四列，
  不建目录/新 ID/明文索引，不改 schema 或任一备份格式/恢复路线。现有收藏 CAS/稳定 intent 不变。
- 给现有 metadata 遍历增加内部有界、可取消的 visitor，避免 UI `snapshots()` 全库 Map；
  keyset 每批至多 20 条，行内只调用 O(1) 请求门。复用既有 65,536 metadata 读取校验上限，
  它不是新增保存条数限制或 1,000 命中预算；超限/损坏明确失败，不截断、不呈现成功空集。
- 收藏开启时，在同一 SQL 事务内流式认证全部合格原件的收藏元数据及当前来源：
  flag/version/mutation/lastFavoriteSourceRevision，正文长度预检及真实 hash/currentRevision、
  generation、捕获时间/合法保存时区、处理策略；排除回收站及任意永久删除阶段。
  媒体空正文可用，AI_NONE 原文人工检索规则不扩张。范围外、未收藏、无匹配原件也认证，
  不把损坏当作“不匹配”。流式摘要包含上述字段、全局 local_search_epoch 与数量，
  私有 owner 回执不保留全库明文/Map；只保留一批 metadata、单行正文和固定大小摘要。
- 初读收藏回执与标签/人物回执共同取得；五类读取后最终共同 SQL 事务重验全部回执、
  各类型集合和来源，提交 ACK 后才发布。收藏关闭时保留现有路径，不新增全库收藏扫描。
  proof 绑定布尔条件及私有收藏回执；旧端口遇显式收藏条件必须报不支持，不能静默忽略。
- 原文向既有候选传 `onlyFavorites=true`，维持 FTS 超集/逐字核验及既有容量，预算前交集。
  统一入口还将同一请求门传入旧候选事务的收藏复核、别名和逐批候选读取；取消先回滚/释放，
  不待整段读取提交后才在外层拒绝。独立原文入口的候选、别名语义与全部上限不改。
  profile2 仍完整认证所有合格历史/来源；逐行显式计算标签、人物和收藏资格，不能短路跳认证；
  仅当前 ACCEPTED 且全部条件满足的逐字命中才消耗 1,000 预算，1,001 整组拒绝。
  A/I/P 保留原有全集合/媒体认证及保存恢复容量，再取交集，不通过过滤绕开损坏。
- 分页/resolve 先按原条件重新认证媒体，再在最后共同事务核旧回执/各集合/所有来源，
  私有 admit 及真正提交返回后确认导航；收藏空→非空、取消→重加的 epoch/version 不可复活旧 proof。
  returnSeed 仅携带条件和既有选择票据，绝不携带可复用收藏回执；返回重新认证选择并重查。

## 生命周期与收藏写入

- 收藏条件开启时，每个 scope 都观察全来源变化，以及收藏 map 的 id/version/flag 语义、
  supports/available/loading/error、待确认写入和 local_search_epoch 变化；不按对象引用误退休。
  包括非命中/屏外原件、可见结果为空、UI-null 导航交接和返回种子；失效清内容并退休旧会话。
- 实际收藏控制器通过来源/版本/目标值准入并接收写 intent 后，在入队执行前退休查询及种子；
  不靠 disabled 控件。CAS 回调可重试，退休副作用放在 CAS 外。既有未知提交/稳定重试不改。
  收藏状态读取不可用或有未结算 intent 时，不发布新“仅收藏”结果/复用旧结果，给明确重试提示。
- 标签/人物选择器只核自己的来源及会话，不因尚未确认收藏而悬停加载；
  真正查询/resolve 的行内门额外核收藏已结算，不能发布未过滤结果。
- 私有 session/request/lifetime 与 owner 仲裁仍为常量大小，不遍历 entries/favorites/bindings；
  完整语义比较只在状态退休和发布边界。延迟 SQL/旧范围/旧布尔值返回不得污染新会话。
  保留 navigation→lifecycle 锁序、真实 SQL 释放和提交 ACK，不以协程取消当资源确认。
