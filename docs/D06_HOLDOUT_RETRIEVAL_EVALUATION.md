# D06 留出集：直接关键词与人工选词后的生产召回

产品冻结基线为 `50e31ae31d4bfd5ab66e4602ed118612994c03f9`。
依据两份原方案 §10.1–10.4、§15；85% 仍是调优目标，不能由本小集签收。

## 1. 留出和独立性的实际含义

- 新建 v3：24 个信息需要，四层各 6 题：改述、否定/引述、人工人物别名、
  日期/时间歧义。仅合成中性素材，附同主题干扰、相反陈述、撤销/删除及旧
  修订；题族、主要内容和情境不复用 v1/v2，也不重用薄荷 UI 演示题。
  这是有意构造的困难小集，不是随机用户样本或用户研究。
- 先冻结方法；再由未看运行结果、候选片段、旧分数及实现专用规则的独立
  策展者编写新 corpus/questions。每题给信息需要、完整问题、允许的上下文，
  不给“应该输入的关键词”。来源有稳定合成 ID、当前修订、捕获时刻/存储
  时区、显式人工事件日期、当前人工人物/别名及失效状态。
- 独立相关性标注者逐题阅读完整合成来源集合，列出所有相关当前 ID+修订、
  排除项与理由、支持性类别及待澄清项；不接触两路线输入、候选或返回结果。
  第二位复核者独立核对，分歧在执行前裁定并保留两份意见及裁定理由。
  不能把本实现作者的预标注改名为“独立复核”；实际身份/会话、可见输入
  的哈希和时间必须有回执。代理裁定明确标为代理，不能写成人类判断。
- 操作选择与 gold 分离：独立操作者只见问题和用户可见的显式上下文，
  H 路另见实际候选片段；不见 corpus、gold、原件 ID、另一条路线的选择、
  输出或分数。D/H 使用隔离会话，记录操作者与会话隔离，报告操作者差异
  的混杂；单代理预写选择只能列为脚本诊断，不能混入独立操作主结果。
- corpus/questions → 双人标注及裁定 → 两路操作计划分别冻结 → 联合执行
  manifest，均以原始 bytes/SHA256、产品源码 blob、身份/可见输入回执串联。
  此后才首次查询。任一独立环节缺失，状态为未独立复核，不发布留出分数。
  根独审继续承担审查；其他角色不写产品树，不另起产品写入者。
- 首轮公开后该版成为固定回归集，不能再称未见留出。看结果后不修标签追分、
  不重选关键词、补录同义词或删失败题；如发现真实标注错误，发布新版本并
  同时保留旧结果、修订理由与重算。产品调优后的独立效果需要新题族留出集。

## 2. 共同 gold 与时间合同

gold 标注“找回对此信息需要有关的素材”，不是“证明肯定事实成立”。否定、
引述、计划、冲突两方可相关，但分别保留“不发生/第三方/未完成/冲突未决”
类别。所有路线共用一个 gold，不能因词不在正文、别名仅在元数据、入口不
理解改述或无法查到，就把相同来源改为不相关。别名命中可相关，不伪造原文
位置/引用。已删除、旧修订及被撤销的别名关系不能成为当前检索的可发布证据。
若 corpus 内只有已删来源，当前 gold 可空，同时记历史相关项和排除理由。

固定参考时刻和时区随题集冻结。每题明确 `resolved` 或 `clarification_required`；
已澄清题显式给捕获/人工事件日期依据、起止包含边界或不限；捕获日期遵从
每个原件存储时区的 LocalDate，不能用统一 UTC 改 gold。没有人工事件日期
不能从正文偷偷补入。相对时间未明确依据时列出不同解释，不能默认一个 gold。
同一日期决定和全部初始筛选同时给 D/H，日期操作不因路线不同而改变信息需要。
来源 gold 还保留相应人物/别名、事件日期等元数据版本及关系，不用正文修订号
替代它们；计分仍按原件去重，元数据版本用于核定同一冻结状态和失效原因。
未澄清题由操作者明确保留/取消，记录零新查询；这是人工决定，不是助手自动
发现歧义。24 题全部留在流程表；待澄清数不藏进 Recall 成功分母。

## 3. 两条真实生产路径与输入公平性

只比较当前同一个“本机原文关键词”入口，不把它叫完整五类问句或自动问答。

- **D 直接关键词**：独立操作者读问题后填写关键词（可空格 AND 词）、显式
  日期决定；不能人为强迫其输入整句问题。冻结计划后通过实际
  `LocalOriginalSearchController.changeInput/inputCommitted/sync`，使用
  `OriginalSearchMode.KEYWORDS`，调用生产 `LocalOriginalSearchMatcher.indexed`
  与 `SqlLocalSearchRepository`。原样问题粘贴只可列附加诊断，不能替代 D，
  也不能用其必然低分作助手提升对照。
- **H 人工选词确认**：运行实际 `QuestionKeywordFragments.propose` 产生候选，
  将完整问题、片段位置、截断标志及显式日期交给隔离操作者。其在未看结果
  前冻结选择/取消/自行输入计划与理由。执行时实际
  `QuestionKeywordController.open/question/choose/terms/basis/dateChoice/from/through/confirm`，
  复用生产导航门、浅绑定、`search.tryChangeInput` 一次提交和实际 `search.sync`。
  不能只调用 prototype、拼好 query 后直查仓库，或由 scorer 按 gold 选片段。
  选择片段按原码点位置和逐字值核，不靠数组下标猜；非候选人工字明确标为输入。
- D 保持其现有输入边界，H 保持 512 码点问题、64 候选、8 词/64 码点确认词
  等真实边界；不为追求分数裁切问题、缩词或强行给 D 增加 H 的限制。
  路线特有的拒绝保留在共同分母和失败表，不能删除不适配题。
- 两路初始数据库为相同冻结语料的独立加密 owner/副本，初始筛选相同。
  来源正文、修订、人工元数据、索引与事件日期快照从真实仓库读取，不能伪造
  UI map 绕 source proof；索引批次收敛上限与实际 profile、依赖/源码哈希入回执。
  D 也走生产控制器而非给 H 额外生命周期覆盖后直接比仓库输出。
- 逐题保全输入、阶段、真实 READY 全候选顺序、前五原件、修订、原文/元数据
  命中类型、SQL 发布确认与实际 resolve 回跳。等待真实控制器完成，超时或
  FAILED/INVALID 不当空 READY；不以 sleep、点击替代 Enter、跳过 proof 或
  重试直到有结果。每题每路线首次运行一次，技术中断重跑必须另列原因/原件。
  记录是否实际触及路径、查询/提交次数；H 确认前零查询及一次提交要可核。
- 主机使用现有 opt-in 离线 init 机制，结果独立目录、唯一测试类、退出回收
  当前进程资源；不污染正常全套结果，不重新跑无关 339/414 或启动 CI。
  首先用非留出校准数据核执行器的真实来源/别名/日期/取消；校准题不计入 24。
  这是 SQLite/AEAD/真实控制器主机验证，不是 MainActivity/Compose、SQLCipher
  设备或性能验证；已通过 UI3 不能替代本次新的质量实测。

## 4. 固定统计口径

单位为当前原件 ID+修订，按生产显示顺序稳定去重取前五，不另按 gold 排序。
两路线 resolved 正 gold 的分母完全相同；`Recall@5 = |top5 ∩ gold| / |gold|`，
宏平均按题，不把同源子项或重复词算多次。某路线拒绝/放弃/报错/无候选的
可评分题仍计 0，不能只报两路都成功的子集；另列每类失败。超过 5 个相关
来源报告理论上限 `min(5,|gold|)/|gold|`，不删宽泛题。

同时逐路线、逐分层报告下列分子/分母与配对逐题结果（小样本不作显著提升声明）：

1. Recall@5；完整候选 Recall 区分缺召回/排序截断，返回 ID+修订与排除原因可复查。
2. 无候选率：`READY 且 0 hits / resolved 题数`；另报
   `READY 且 0 hits / 实际 READY 数`。未查询、无效、超时、FAILED 各自计数，
   不能混成真实空结果，也不能从端到端流程表消失。
3. 空 gold 不计 Recall=1，单列数目、返回率、返回来源；否定相关不等于空 gold。
   已删除/旧版本/未认证来源返回单列严重正确性失败，不用均分遮盖。
4. “需要人工修改比例”采用可观察口径：H 操作计划中**本次选择需要手工键入/
   删改关键词**的题数 / 全部 resolved 题数；同时列实际执行编辑数、未完成数。
   仅勾片段和必需日期确认不算关键词编辑；手工日期输入单列。操作者在看结果
   前记理由及计划最终词是否全部存在候选；这是**本次盲选计划的编辑需求**，
   不证明所有可能选择的最少必要编辑，也不是自动选词准确率。
   不先人为指定词再用“是否被提取”冒充独立操作；结果后修改另属诊断，不入首轮。
5. D 的人工输入负担、H 的片段选择数/编辑/日期选择分别列原始计数，不将
   H 100% 必须人工确认包装为零人工，也不由代理动作推算真实用户耗时。

失败分布至少区分：词法/改述缺候选、候选有但前五未覆盖、别名仅元数据、
冲突/否定/引用误解释风险、日期待澄清、来源失效、拒绝/取消、技术失败。
检索相关性分数不能证明答案支持性，尤其不得从结果生成肯定结论。
