## 先纠正标注口径

v1 的记录、标签、观察及分数逐字保留，不按新结果追改。v2
`relevance-v2.json` 将信息需要的相关性 gold 与入口实现能力/引文准入分开：
coffee 的记录、人工别名对应原件，对各入口具有同一相关性；大小写能力
或“只逐字查正文”不足应报告成能力差异，不能改成空 gold 奖励实现。
纯别名来源相关，但仍不得伪造为正文引文；同时报告这一准入限制。
“上个月的展览”没有指定捕获/实际事件时间，标为待澄清，列出两套解释，
不选择一个当唯一答案。它不进入 Recall 分母，也不作为成功查询计数。
事件时间的备选相关性是人工阅读正文得到的解释，不声称库里已有人工事件
日期；缺失的事件日期不能由正文自动补入筛选。
v2 用不变 v1 观察重计只是新标注视角，不是运行/产品效果改善。

## 最小产品入口

在回忆的“本机原文查找”旁增加独立按钮“从问题里选词”。原输入、精确
片段及统一找回保留。助手仅处理用户输入的问题，不读取库中内容作提词。
它止于用户确认的关键词查找，不自动开启问答、采纳偏好或创建任务。

1. 输入问题，完整保留原字、否定、条件和引号。最多512码点，不落盘、
   不进 Bundle/Saver、日志或诊断。退出/后台/重建退休并解除内容引用，
   不声称 JVM 字符串被可靠物理清零。
2. 显示有原问题位置的“候选片段”，**默认全部不选**。通用可验证规则：
   汉字连续段的整段（最多16码点）及长度4/3/2/1的相邻片段；英文/数字
   连续段整词（最多16码点），超长词可在确认词编辑处自行输入。
   所有候选必须等于原问题中精确半开码点区间，不删除否定、引述或条件，
   不含停用词词典、四样本专用分支、同义替换或新模型/embedding。
3. 最多64个不重复候选；按原位置和上述长度顺序，超限明示“只展示部分
   候选，可以直接编辑关键词”。这不是中文语义分词/意图理解。用户可选、
   删改或自行输入；编辑新增文字明确属于用户输入，不冒充提取结果。
4. 预览最终关键词（最多8词，含分隔空格总计64码点，不能为空）。显示
   “全部包含”、当前日期依据/范围及原有标签/人物/收藏/图片条件，用户
   明确确认后才复用真实 `LocalOriginalSearchMatcher.indexed` 召回。
   空词、无效 Unicode、控制字符或越限零检索，不静默截断/改写。

### 相对日期与偏好冲突的独立合同

- **不解析问题中的日期。** 确认页总是明确“问题里的时间不会自动变成筛选”，
  要求用户选择沿用/修改现有日期条件并确认日期依据（捕获或人工事件日期）。
  这不靠硬编码检测“上个月”。没有这一决定时不可确认查找；空日期必须
  用户明确选择“不限”。事件日期缺失/状态未确认沿用现有拒绝路径。
- 确认页可沿用现有日期，或用相同格式的手工起止日期/依据控件修改私有
  草稿，不必丢掉问题重输。日期选择必须明确为沿用、不限或手工范围；
  无默认已确认选择。草稿不立即写入规范搜索输入，不新造日历推断或
  自动使用正文日期。已审日期/条件变化则确认失效。
- 不改写“喜欢→偏好”，不把“现在”当自动取代指令。匹配不到可编辑词，
  匹配到冲突则保留各份原文和日期，不生成肯定答案或唯一偏好结论。
- 否定/条件/他人引述仍可作为相关素材，完整显示上下文；查回不等于
  发生/支持性验证，不用引用存在代替答案被证据支持。

## 复用接线与退休约束（实施后必须实测）

- 主改动预计只在 MainActivity、原文查找展示及一个小型内存控制器；
  候选生成是纯函数，不改仓库接口/索引/schema/备份，不走统一逐字入口
  拼接空格。该入口首片仅接原文关键词查找，不宣称五类问句检索已完成。
- `searchEnabled/evidenceEnabled` 在助手打开期间显式为false。打开即
  `search.invalidateInput()`、清证据及返回锚，暂停旧结果；否则当前
  SideEffect 会立即用旧输入重新开查询。提词自身不发 SQL/媒体请求。
- 取消保留原有规范输入，但旧 proof 不恢复；关闭后既有输入若重查，
  必须取得新 proof。修改问题或词、取消、后台、离开路由、dispose 递增
  私有 session/request/lifetime；迟到提词事件、双击确认不得重复写查询。
- 确认必须在 `NavigationOwner.publish(expectedGeneration)` 仲裁内校验
  同一助手会话/问题版本/最终词/已审规范输入条件/当前owner与可用状态。
  锁序仅 navigation→helper→search，helper/search 回调不得反向获取导航锁。
  不能只在 UI-null 后靠按钮 disabled 或旧 request 判断。
- **真实代码中的实施前置项：** 当前 MainActivity 的 onBeforeSearchInput
  把 ownsNavigation 放在 `search.beforeInputCommit` 的锁内，若干模式/标签/
  人物回调也在 `search.changeInput` 内读导航。不能一边新增上述锁序，一边
  保留这些 search→navigation 嵌套。实施时须把同组规范输入回调统一改为
  `navigation.publish` 先仲裁，内部只运行不再获取导航锁的搜索元数据准入/
  输入变更；Foundation transformation 内仍只改私有退休元数据，不改Flow/
  Compose/输入文本。不得仅把导航检查移到锁外留下竞态。需独审完整调用图、
  重入拒绝和双线程屏障，当前非出货探针不证明这些应用接线已安全。
- 一次性确认经 `search.changeInput` 先退休旧请求，再在同一主线程 Compose
  snapshot 内设置 KEYWORDS 模式、query/from/through TextFieldState、显式
  确认的日期依据与 modeGeneration，不能先发布半套词/日期。
  程序化 edit 不依赖 InputTransformation；不能在 TextField edit/CAS 内
  调原有 onBeforeSearchInput 或做外部回调。日期只按明确草稿改动，其余
  标签/人物/收藏/图片条件不隐式改变。
  剩余旧 SQL 可正常释放，但新发布始终使用现有完整来源/epoch认证。
- 复用原文入口已有精确原件跳转、版本/删除/AI_NONE 引文排除、别名与
  标签“仅查找非引文”限制、范围/owner proof。返回不得重新显示助手草稿。

## 本轮可执行证据与后续验收

v2 独立新词探针23原件/10问题，含分开干扰、否定/引用、借还、补充平面汉字、
英文大小写、删除/修订、冲突和日期歧义。先冻结文件和SHA，再运行。
`checks/retrieval-quality/v2/src` 是**非出货设计原型**，只在显式 init 脚本
加入主机评估源集；不接真实应用，不改正常 CI/生产代码。
同一真实原文仓库分别记录原问句与预先写定的合成用户确认词，另记候选
是否包含这些词。**确认词由脚本扮演用户选择，不是算法自动选对，更非用户研究。**
歧义日期无决定时不查；“喜欢/偏好”保留能力缺口。不用旧四条问句造规则。
首次原型整段候选未限长度；资源复查后仅增加16码点上限并做同冻结集必要
回归，不改标签或语义规则。首次日志/原型也保全，避免把资源修订后的源码
冒充首次受测源码。当前探针以 revision2 记录这一差异。

设计通过后的实现验收才包括：确认前零新检索、编辑/取消/双击、旧session
迟到、确认前暂停/导航、条件变更/无效日期、实际SQL源变更与精确跳转、
200%横竖屏滚动/键盘主操作。当前原型不能替代这些测试或设备/TalkBack/
SQLCipher/真实性能验收；不声称达到85%发布目标。
