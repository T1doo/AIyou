## 实际修复

1. 横屏添加按钮原先沿整屏边缘排列，超出了居中内容列。先约束到内容列后，
   模拟器截图又发现它仍覆盖任务卡片右侧。新增的“不遮挡任务行”断言在旧布局
   明确失败，随后将短屏／大字体的创建动作放入顶部操作行。普通竖屏继续使用
   原有浮动入口；唯一入口、可用性和继续编辑行为不变。
2. 回顾返回会让“更多”折叠，调用工具入口消失。现在只在当前存储上下文中保留
   顶层展开布尔值；不保留查询、来源证明、结果或操作回调，不进入 SavedState。
   子弹层保持关闭。准备状态、存储 owner 或页面重建变化时重置该布尔值。
3. owner 更换时，“更多”的旧节点也随之退场。回归直接保留旧语义动作，核对
   固定版本 Compose 将其作为已脱离的节点拒绝，且新上下文的菜单保持收起。
   这不是设备 TalkBack 事件验证，也没有修改持久化或权限实现。
4. 待办日期、详情、修改标题与提醒测试现在先操作真实展开入口。关闭保留草稿
   与“放弃输入→确认丢弃”分别验证，未改回旧的关闭即丢弃行为。组数量保留在
   语义状态中，完整日期／时区／偏移留在可展开详情，不增加常显说明小字。
