# 用户主动导出当前原文与手工标签

本切片对应原计划 F08、§14.4 中的开放格式导出的一部分。仅处理用户明确选定的当前原文和手工标签，支持 Markdown、JSONL；不包含附件、历史版本、待办、草稿、AI 派生结果、连接授权或任何密钥。完整加密备份、恢复、跨设备迁移、D08 和 D02 生产重启原生验收仍为 OPEN。原始主计划和架构文档保持原样。

## 用户操作与文件范围

从“回忆”选择“导出选定原文”，默认不选任何记录。用户选择原文和格式，预览包含 ID、原文版本、记录时间与 IANA 时区、正文 SHA-256、独立标签版本及标签。长正文仅显示前 300 个 Unicode 字符，文件包含完整正文。每次最多 20 条、总正文最多 250,000 UTF-16 单元、最终 UTF-8 文件最多 2 MiB；超过界限明确失败，需减少选择，不截断文件或隐式改变范围。

普通导出为明文，不能完整恢复应用。用户必须确认这份快照以及明文、云盘和覆盖已有文件的风险，再通过系统 `ACTION_CREATE_DOCUMENT` 自行选择目的地。建议文件名固定为 `AIyou-current-originals.md` 或 `.jsonl`，不含记录标题或 ID。应用不自动分享、不调用外部服务、不申请广泛存储权限、不持久取得 URI 权限、不导出密钥，也不建立明文临时文件。开发和测试全部使用合成记录；用户实际运行时选择的文件服务可能将内容传往其自行选择的云盘。

## 一致性与确认

生产仓库在同一计数 SQL 事务和同一连接内读取所选当前正文、正文哈希和经现有 AEAD 认证的手工标签。缺失、已删除、版本变化、正文哈希错误、标签认证失败均无法成功准备导出。UI 缓存不充当事实源；没有标签的原文以标签版本 0、空标签列表表达。无需数据库迁移，Room 继续使用已检入的 v6。

预览之后、选择器之前以及文件写入之前再次读取实际仓库并核对整份确认快照。变化会阻止写入，要求用户点击“重新预览最新原文”，再重新确认；不会自动把新版本替换进去。写入已经开始后使用不可变快照字节，期间任何变化都不能把两个版本混入一个文件。写入后再次检查仓库；如果变化或当前读取失败，成功提示准确说明文件与确认快照一致，但不包含后来变化，或当前本机状态暂不能核对。

JSONL 首行 manifest 标明格式版本、快照 ID、创建时间、记录数量、明文性质及包含/排除范围。每条记录保留逐字原文与元数据；结束行包含记录数量以及所有记录行（含 LF）的 SHA-256。Markdown 用足够长的代码围栏显示元数据和原文，正文中的 HTML、链接和反引号不会逸出围栏；JSON 元数据提供可精确还原的原始换行与正文。文件和所有异常、状态对象的日志表示不包含原文、标签、URI 或 provider 异常详情。

只有流写入、flush、关闭、同一 URI 全字节读回、读取关闭全部成功才显示“已写入并读取核对，与确认快照一致”。该确认不保证云盘的后续同步或永久持久性，也不是备份恢复证明。[ContentResolver 文档](https://developer.android.com/reference/android/content/ContentResolver) 明确指出文件模式取决于具体 provider。

## 取消、迟到结果与部分文件

选择器取消不会调用写入，下一次选择须重新确认风险。准备和选择的异步结果在状态 CAS 内检查 session、epoch、阶段与可用性；选择器 UUID 仅由当前 ViewModel 在内存持有，不从 SavedState 接管旧 UUID。关闭、取消、销毁或离开回忆页会撤销旧操作。配置重建保留同一 VM 的选择器所有权且不重复启动；新 VM 不接收旧结果。注册使用非生命周期重载，并在 composition 结束时注销，符合 [ActivityResultRegistry 文档](https://developer.android.com/reference/androidx/activity/result/ActivityResultRegistry)。

通用文件服务不提供原子替换：创建目的地可能留下空文件，写入、关闭或读回失败以及取消可能留下部分文件。应用不显示成功，也不自动删除或重新覆盖该 URI。停止写入需等文件服务当前操作返回，之后关闭流；文件服务若阻塞，不能承诺立即取消。用户可以自行检查文件或另行确认“删除所选导出文件”。删除确认同时绑定 session 和精确目标 UUID，迟到的文件 A 确认不能删除随后选定的文件 B。选了已有文件时，该删除同样会删除已有文件，确认框明确说明不可在应用内撤销。删除失败保留目标和错误，不显示成功；删除后需重新确认风险并重新选择目的地。

原文、标签、选中集合、快照、确认状态及文件对象只放在内存，不使用 Saver/Bundle。全局记录读取失败或当前版本不匹配时隐藏正文和标签预览，保留待处理状态以便恢复或关闭。选择器明确加入 `CATEGORY_OPENABLE`，限定可表示成流的文件，不增加任何 URI 授权标志或权限。

## 验证边界

Host SQL 测试实际使用已导出的 v6 表、生产 SQL 和标签密码学，两个独立 SQLite PID 证明快照事务阻止混合读；不冒充 SQLCipher Android 验收。控制器测试覆盖确认前置、版本变化、写入期间变化、取消、关闭/权限/读回失败、显式删除、迟到结果以及成功结果与真实状态 CAS 之间的取消/关闭/销毁。实际 VM 队列测试证明导出期间输入立即响应并在队列继续后真正保存草稿。

Compose JVM 测试使用实际 UI、控制器、ActivityResultRegistry、系统 intent 和合成端口；平台文档测试使用实际 ContentResolver 与合成 ContentProvider 文件，确认 `wt` 截断和同一文件读回、权限拒绝、明确删除以及拒绝非 content URI。它们不启动原生系统文件选择器，不证明真机 provider、云盘同步、设备重启或跨设备恢复。设备选择器 / 生产重启：**NOT RUN**。既有 35 项原生方法和 2 个外部探针维持现有编译/DEX 清单，本切片没有新增原生通过项。

交付时以精确 Git HEAD 的严格 CI 及实际测试 XML 为验收依据，保留失败尝试与修复记录。不得将编译成功、APK 生成、自动化 UI JVM 模拟或此前模块的原生方法编译表述为设备验收通过。
