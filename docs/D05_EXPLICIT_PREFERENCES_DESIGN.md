## 真实缺口与本片范围

两份原方案 §10.1–10.2 区分事件、稳定事实/偏好、回顾与任务，要求明确陈述与审阅状态分离、
待确认、纠正、取代和历史有效区间，不把当次情绪当成人格或稳定偏好。
当前 `SourceMemoryKind` 仅 EVENT / OCCASION_EMOTION；`D05_SOURCE_MEMORIES.md` 明确不建立稳定偏好。
现有 proposed/accepted/rejected/superseded/revoked、纠正链和来源校验是事件产品合同；
没有普通偏好内容、有效区间、跨来源冲突取代与对应完整备份分派。应用显示/回顾设置偏好不是该记忆能力。

本片只做：当前原文 → 用户逐字选择本人明确自述 → 选择/创建普通偏好主题 → 存为待确认 →
另一次确认采纳 → 人工纠正或撤回 → 回忆中按主题查看并查回原文。
限口味、休闲活动、呈现习惯等普通偏好；无身份/关系/健康诊断/人格/敏感类别菜单。
不自动抽取、分类、语义查重、冲突判断、事实核验、时间解析，不调用模型或网络，不创建任务/提醒。
采纳只是用户确认保留此说法，不证明客观真假、永久成立或已获远端处理授权。

界面要求用户明确确认“这是我本人的明确自述，属于普通偏好”，并提示引用/假设/计划/当次情绪不应归入。
系统只核逐字来源和操作合同，不能声称能自动识别所有敏感表达、转述或错误分类。
例如“我平时更喜欢淡茶”可由用户选择；不能从“今天不想喝咖啡”自动生成长期讨厌咖啡。
此片不补其他稳定事实/身份关系，不把完整 D05 宣称完成。

## 内容、审阅与可用性分离

新增独立 SourcePreference 模型/API，不给 SourceMemoryKind 添加 PREFERENCE，也不复用其业务密文。

| 层次 | 合同 |
| --- | --- |
| 不可变来源绑定 | preferenceId、entryId/revision/hash/generation、捕获时间/时区/原政策、创建 epoch |
| 内容版本 | 连续 contentRevision 1..8；唯一逐字引用/code-point范围；手动主题 id/标签；用户声明有效区间；创建时间 |
| 审阅记录 | 与内容分开保存、按 contentRevision 关联的检查点：reviewState、priorReview、reviewedAt、最后操作摘要、取代关系；普通审阅不增加内容版本 |
| 行 CAS | rowVersion 每次写入递增；绑定完整 expected source + rowVersion + contentRevision + previousReview + 请求元组 |
| 来源可用性 | AVAILABLE / INVALIDATED / UNAVAILABLE 与审阅状态独立；失效不是用户拒绝或撤回，存储异常不冒充空列表 |

内容引用来自当前原文，逐字唯一匹配，最多320 code points；无自由改写“偏好结论”、置信度或自动主语推断。
同一行全部内容版本仍绑定同一不可变来源版本；改原文后不能以纠正旧候选跨版本重绑，须从新原文另建候选。
主题由用户明确创建或从可认证现有主题选择，opaque UUID，不按文本相似度合并。
主题标签最多40 code points、无控制字符；同主题标签一致，本片不做主题重命名/合并/跨主题搬移。
主题 id/标签在一条偏好内固定；纠正限逐字片段和有效区间，改主题需明确新建，旧条目不静默搬家。
跨主题不承诺发现语义冲突，不能把新建同义主题当作系统已确认可并行成立。

### 有效区间

默认 `UNSPECIFIED`，两端均显示“未说明”；不将 capturedAt、创建/采纳/纠正时间当作 validFrom。
可由用户单独声明按日区间：显式 IANA zone、可未知的起点、可未知的终点；至少一端已知才是 USER_DATES。
已知范围按 `[fromDate, untilDateExclusive)`，起点须早于终点；UI 若选择最后有效日，显式转换为次日，溢出拒绝。
未知端表示不知道，不是负无穷/永远；“最近”“以前”“现在”等词不解析为日期。
不同主题/时区或未知端不自动计算冲突。有效区间只属于此自述，不是系统事实有效性认证。
第一片没有“当前事实”推导过滤；已采纳列表始终展示所声明区间和未知标志，不能统称“当前有效偏好”。

## 审阅、纠正与冲突取代

新建必为 PROPOSED，保存待审与 ACCEPT 是两个不同确认 token。PROPOSED 可 ACCEPT / REJECT。
ACCEPTED 可 REVOKE；历史保留，但撤回立即退出已采纳查询，不改变原文、任务或源政策。
非 SUPERSEDED 的条目可 CORRECT，必须真有片段/区间变化：旧内容不改，旧审阅记录转 SUPERSEDED 并保留 priorReview，
追加内容版本及新的 PROPOSED 审阅，必须再次单独采纳。到8版仍可拒绝/撤回，不可再纠正。
本片不提供 REOPEN；REJECTED/REVOKED 的原内容不直接恢复采纳，未改内容要重新考虑须用户明确另建候选。
SUPERSEDED 只读，不能恢复为当前；任何操作不自动复活更旧偏好。
每个内容版本最多采纳一次，避免同一版本反复采纳产生无界取代关系；不是每次点击的完整审计日志。

用户选择同一主题/上下文即声明这些自述应作为同一组审阅；系统不判断它们在语言上是否矛盾。
组内最多一条“当前内容已采纳且来源可用”的偏好。无旧采纳时，普通 ACCEPT 单独提交。
有旧采纳时，普通 ACCEPT 必须拒绝并展示需处理的旧项；不得按时间戳、分数或所谓新意图自动覆盖。
用户可退出，也可在专用比较确认中选择“采纳此条并取代已展示的那一条”：并排显示双方引用、来源版本、
原审阅和区间，说明取代不代表旧话曾经错误，也不自动补齐旧话的有效终点。

`acceptReplacing(newExpected, oldExpected, mutationId, requestedAt)` 在同一真实 SQL 写事务内：
认证两行/全部内容、来源政策/删除/版本/generation、同一主题、new=PROPOSED、old=ACCEPTED；
认证组内所有其他可用条目并确认没有第三个已采纳项；双方 CAS 各递增一次。
旧项改为 SUPERSEDED，新项改为 ACCEPTED，共享完整请求摘要/operationId和互指的目标内容版本。
任一 CAS/AEAD/读回失败全部回滚；丢 ACK 的同一请求只返回相同已提交回执，不二次写入。
并发或独立连接必须由实际 SQLite 写事务/行 CAS 串行化并以竞争回归证明，不靠 UI 禁用或单个 controller 计数。

取代链接属于独立审阅关系，按内容版本保存；只存对方 opaque preferenceId、目标内容版本和操作标识，
不复制对方引用、主题、区间或来源正文/hash。完整请求摘要可绑定双方来源和 expected 值，但不保留对方明文材料。
后续纠正保留当时取代的内容版本关系；新内容仍待审。撤回或来源失效不使另一项自动重新采纳。
每个内容版本至多一次采纳使每行关系数最多8，既保留历史又有界。

如果链接目标后来失效/被永久删除，只显示“历史取代关系的原项已不可用”，不展示缓存的旧内容或重建证据。
另一项仅靠自己仍有效的单一来源成立，不能把失效目标当第二来源。不可解析链接不构成当前取代权限。
旧请求涉及的任一来源已失效时，拒绝重放/确认为双方仍有效；刷新可显示有限的实际当前状态，不假报整次成功。

## 持久化、来源失效与 owner

提议沿用 `local_candidate_batches` 的第三种产品格式 `ruleVersion=3`，仅作存储 discriminator，
并有专用 SourcePreferenceRepository/Cipher/解码器；现有格式1摘录、格式2事件仓库在 SQL WHERE 先隔离再限量，
按 id 请求也拒绝跨格式。物理 state 仍 READY，所有业务审阅在密文；来源失效沿用 INVALIDATED+空 payload。
现有表无 profile枚举约束，既有来源触发器覆盖所有 READY 格式，故提议不改 Room v15 表/迁移。
这必须以真实 schema/触发器测试确认，不能只加枚举就自称完成。

专用用途 HMAC 派生 AES-GCM 子密钥，不复用 SourceMemoryCipher 用途、外层magic或 enum解析；同一数据库 key/排空 owner，
无新 Keystore alias、凭据或依赖。AAD 绑定产品/版本、行id、来源绑定、rowVersion、物理state、创建时间及完整请求摘要。
密文含捕获元数据、主题、全部内容版本/审阅记录/有限关系及最后请求合同；严格检查枚举/身份/连续版本/长度/EOF。
plaintext≤32768 B、cipher≤32797 B；用后清零、owner 排空后清子密钥，异常不返回半份资料。
日志/toString仅给出类型、状态和版本，不打印引用、主题、区间、来源正文或完整请求；无明文临时文件。

每个当前原文最多20条 READY 偏好、全库最多128条 READY 偏好；全候选物理行仍受既有备份4096条上限。
同组冲突检查先按 profile3/state 查询元数据，LIMIT129及密文总量≤4MiB，再认证全部可用行；不能只检查当前分页。
来源原文按条有界认证后释放，不同时缓存128份原文；沿用每条100000 UTF-16单元/有效Unicode的上限。
主题在密文中，不建立明文偏好词索引。读取一行损坏时不能跳过它并假定组内没有其他已采纳项。
失效的空密文行不占 READY 名额；容量不足明确报错，不静默丢条目或清理未知资料。

创建预览绑定完整来源及现有全局 epoch；出队/事务入口复验，精确创建重试先查回执再查容量，
避免成功后丢 ACK 在容量边界被错误新建或拒绝。已有条目 mutation 依行/源 CAS，不受无关源 epoch 变化影响。
所有读取、创建、采纳、纠正、撤回、替代和来源跳转均核当前 revision/hash/generation、捕获元数据、政策、
删除标记和任意阶段永久删除收据。AI_NONE 不可建候选；独立改处理范围须另行确认，不自动授权。
原文修订、删除/回收站、处理政策/generation变化使该来源 profile3 内容立即失效并清密文；重新允许、回收站恢复不复活。
永久删除仍删除该来源所有格式的物理行，不增加只删格式1/2的过滤。链接关系按上述不可解析规则处理，不保留旧内容。

普通偏好借用同一 `DrainingRecordsSqlDatabase` 和实际串行 IO actor；新 EntryRepository/VM DI 显式挂接能力，
不另起 owner 或绕过锁屏。UI 准入、排队命令、事务前均核 owner/session/request；已进入的事务由原 owner lease
完成提交或回滚，导航/owner退休后不得向新界面发布旧结果或让旧确认提交新请求。结束后随 owner 擦 key。
并行来源写/锁/恢复须沿既有共享 gate 和排空合同接线验证，不以按钮禁用代替 repository 校验。

## 全备份与格式兼容

当前逻辑全备份只允许候选格式1/2，portable转换/验证也只分派1/2；格式3必须显式扩展，不能默默落在旧 v8/v9。
提议有偏好行（含失效行）或 V10 导入回执时，写独立完整备份 v10 magic/逻辑版本和 FULL_BACKUP_IMPORT_V10 回执。
无这些数据时保留当前无音频v8/有音频v9选择；v8/v9读取仍只许旧profile1/2，不能以新类型冒充旧版本。
v10保留原13表布局及限额，允许profile3并专用portable/全局校验；沿用v9音频描述段，即使数量0也显式编码。
`RecordMediaPackageCipher.sealFull/openFull/scanFull` 外头/逻辑版本、codec、digest/current、import journal/完成回执、
restore/verifyRestored、summary及丢 ACK 幂等全部同审同改，不能只改 codec 的 allowed set。
v10是完整资料库命名空间，不能与选定记录包的audio-media-v9或legacy baseVersion嵌套混淆。

逐行验证来源精确引用、全部历史/审阅与 AEAD；全局验证主题唯一当前采纳、重复id、版本/关系一致性和边界容量。
可解析的双向取代链接必须匹配双方 operationId/内容版本/历史状态；指向不可用/不存在条目仅作不可解析历史标记，
不据此认可原替代请求、补造旧内容或越过组内唯一采纳检查。错配的仍存活双向关系拒绝整个文档。
导入必须认证完元数据与关系后才写恢复意图，空目标/现有来源图/副作用隔离沿既有全备份合同。
恢复保留用户内容/区间/审阅历史，重加密到新 owner key；REMOTE_ALLOWED 统一LOCAL_ONLY，联网授权/密钥不导出。
接受状态不授予任务/提醒/联网权限，不因恢复自动生成新候选或重新采纳。不可解析关系不能用于旧 mutation 回放确认。
有偏好却不支持v10时必须拒绝导出/导入，不能降级漏掉偏好；旧应用对v10明确不支持。
选定记录包/手工文本导出本片不承诺包含偏好，UI须如实区分完整备份。

## 生产 UI 与验收路径

原文详情增加独立“普通偏好自述”入口；回忆增加其专用待确认/已采纳浏览，不混入事件/情绪列表或普通记录数。
每页最多20条，先 SQL 类型/来源过滤后限量，认证当前页和来源再发布；分页/本页数不冒充全库有效偏好总数。
已采纳只读浏览不自动改变范围/审阅；点击出处重新核行与源证明，再跳现有原文 code-point 高亮。
表单、逐字片段、主题及确认 token 仅内存，禁 SaveableStateRegistry；关闭/恢复/导航/锁使旧 authority失效。
未知写结果不显示成功/假空；保留同一 immutable intent核对，后续观察变化则拒绝旧操作并明确刷新。
纠正、撤回与替代各有独立预览/取消/确认；w320dp和200%字体、触控≥48dp与Lazy节点组合按实际控件测试。
所有示例合成中性；不要把 RAM UI fixture 说成真实 SQLCipher、模型或隐私语义理解。

设计 ACK 后的必要验证按风险选取，不为数量补外围测试：

- 领域：原文否定/引用不被改写；Unicode唯一范围；未知区间不等于永久；日期/zone/EOF/容量；状态与内容版本分离；
  存待审与采纳两次确认；纠正重待审；满内容版本仍可撤回；无 REOPEN/自动恢复。
- 实际 SQLite/JCA：profile1/2/3混存隔离、AEAD替换/损坏、独立连接并发采纳/纠正/替代、第二行CAS失败全回滚、
  双行提交丢ACK精确重试、请求改变/第三个已采纳/隐藏损坏拒绝、来源失效或永久删除后的关系和重放边界。
- 真实来源生命周期：修订/AI_NONE/回收站/恢复/永久删除/访问行ABA/旧owner/迟到actor，禁止复活或跨owner提交。
- 完整备份：旧v8/v9原样读；v10偏好单独及与音频、事件日期、图片、草稿、历史/取代/撤回/失效混合，
  冷重开→导出→新key空目标恢复→再导出语义往返；版本谎报/未知profile/不一致关系/错误口令/截断/EOF全拒绝，
  丢ACK不重复恢复，不恢复远端授权，不触发旧日期+音频legacy嵌套回归。
- 实际 controller/VM队列和两套Sync生产源；UI双倍字体的存待审→单独采纳→纠正再确认→撤回取消/确认→原文高亮，
  失败/恢复/旧闭包/冲突比较与精确一次写入。Compose是JVM模拟，原生编译/DEX不是设备执行。
