1. 总体判断：不是从零开发，也不能称为完整正式版

1.1 当前真正处于什么阶段

AIyou 已有安卓开发预览版、本地记录及附件、检索、来源处理、待办提醒和备份恢复等接线；同时有一套持续完善的 Skyglass 浏览器交互原型。原型在 867f86ed 已针对按钮主次、编辑面板、组合筛选、草稿和减少动态进行了修正。[S01][S04][S05]

准确的阶段描述是：本地产品链路已有实现，新视觉方案已有交互验证，原生迁移和完整产品验收尚未闭合。 不能把它简单称为“做到 D02”，也不能因为某些后期模块存在就称为“D00–D09 已完成”。版本名 0.0.4-d02-ui 不能代替功能与验收状态。[S01][S02]

原始设计的两类模型协议、AI 整理、有来源问答，以及图片／语音能力，和当前默认离线预览的实际能力之间仍有差距。真实模型与自动 ASR 未启用，新图片 OCR 提取器不可用。这些属于能力未启用／未接通，不能全部改写为“只差真机测试”。[S01]

1.2 最高优先级的五件事

顺序 必须解决的事项 为什么现在做
1 恢复可复查的当前原生构建与测试基线 最近查询到的原生 CI 在领域代码编译阶段失败；当前 SHA 未查到关联 Actions 运行，不能继承旧的绿色结果
2 将已认可的 Skyglass 设计落实到原生组件与真实页面 原型修好不等于 APK 已有同样的界面、状态和交互
3 建立页面／功能保全清单，覆盖详情与二级流程 不能只搬三张首页，把原文、附件、版本、来源、回收站、隐私和恢复操作丢掉
4 关闭保存、删除、恢复、提醒等高风险验收缺口 私人记忆产品的精致感不能以数据丢失、误提醒或隐私状态失真为代价
5 明确本地预览与完整 v0.1 的交付边界 避免没有真实 AI／OCR／ASR 却使用暗示可用的入口与文案，也避免擅自扩大到云同步等后续版本

这是实施顺序建议，不是对所有现有功能都存在故障的断言。[S01][S06][S07]

4. 前端方向与设计系统：明确保留项和改动边界

4.1 保留项

保留天空、云、海面和远山，背景不加入玻璃摆件、无意义气泡或悬浮装饰。保留晴空蓝／桃色晚霞／星夜紫的整体色彩关系，玻璃用于 UI 表面。保留可关闭、可减少的适度动态，以及小型噜噜入口。保持“此刻／回忆／待办”三入口，不新增功能来填满留白。

目标不是让每屏更满，而是让记录与任务更容易读、输入更直接、状态更可信。天空留白是允许的，重复日期、默认正常状态和过大的固定容器不是必需的。

4.2 单一设计来源与 Token

建议在现有 design/ 结构内建立 Skyglass 语义 Token 和状态说明；路径由 Codex 在盘点后确定，不假设下列文件已经存在。旧 Token 的业务语义保留，避免所有调用点一次性改名。

语义层 建议 Token 范围 用法

表面 welcome、reading、input、sheet、navigation 分别控制填色／透色／边缘，不共用一个透明度

时间／必要辅助 12–13／18 sp 足够对比，重要异常可以更醒目
底栏文字 12／16 sp 不隐藏未选中标签，不用全大写英文替代

使用系统中文无衬线字体与稳定回退；不为视觉效果额外引入未经审查的字体资源。sp 跟随字体缩放，dp 用于布局，不将字号统一锁成像素。边距从 20 dp 起，窄屏可用 16 dp；间距基于 4／8 dp 节奏。建议卡片圆角以 16–20 dp 为基础、面板上角 24 dp 左右，最终应以已有认可画面比较，不再无条件增大圆角。

视觉图标约 20–24 dp，交互目标至少 48×48 dp；可见图标与触区分开设计，避免隐形触区相互重叠。Compose 的部分组件有默认最小目标与语义，迁移时仍需检查自定义控件。[R01]

4.4 玻璃的三层用途

欢迎与轻工具层： 透出较多环境色，少阴影，避免欢迎区比正文更厚。
阅读层： 稳定的磨砂底与轻边缘；允许低频景观色穿透，但不能让云纹或流光干扰正文。
输入与面板层： 最稳定，必要时接近不透明；编辑可靠性优先于“更透明”。

晴空避免整片亮白厚边；晚霞保留暖灰／桃色环境透色，不继续加粉色装饰；星夜避免所有表面变成同一种厚重深蓝，允许紫色低频透色，同时保持主操作可见。这些是视觉打磨方向；最终须看最新原型和原生截图，不沿用已修复画面的缺陷描述。

对比检查用最终合成像素和实际状态：常规正文以 4.5:1 为验收基线，必要的非文字控件与状态识别以 3:1 为基线。装饰性描边不必都强到 3:1；但控件不能仅靠低对比装饰边缘辨认。WCAG 的“大字号”判定来自 Web 单位，不直接等同安卓 sp。[R04][R05]

4.5 安卓玻璃实现不能照搬 CSS backdrop-filter

Compose Modifier.blur 的官方支持范围是 Android 12 及以上；不能把它当作 API 26 全范围可用的自动背景毛玻璃，也不能对整个含文字的卡片直接 blur。[R03]

优先方案是：共享景观层 + 有限的环境色／预处理模糊素材 + 清晰的语义表面。需要实时背景采样时先验证实现与成本，避免每张滚动卡重复采样／模糊全屏。API 26–30 或性能降级时，使用同主题的稳定透色渐变和轻边缘，保持色彩与空间关系，不退化成纯白模板。

记录降级前后截图、长列表滚动与内存表现。不要为追求毛玻璃临时引入未经核验的大型渲染依赖或升级整套工具链。

5. 三主页面与二级页面的具体方案

5.1 此刻：让输入简单，让原文先被看见

保留已改内容： 紧凑欢迎区、底部输入停靠、较强正文、附件轻量工具。不要重新扩大欢迎卡或恢复默认说明小字。

原生完成要求： 欢迎区按内容自适应，不在大字时用固定 72 dp 裁切；噜噜入口保持小型。输入未聚焦时紧凑，聚焦后随内容与键盘扩展；不同时保留一个占高度的假输入卡和另一个完整编辑器。展开铅笔只表示展开编辑，保存使用明确完成动作，两个语义不能静默互换。

文字、图片和音频单独或混合时都应有可提交判定；不能仅因正文为空就禁用一个合法的图片／音频记录。没有任何可保存内容时禁用。保存中防重复；成功以实际持久化为准；失败保留正文与附件，并允许重试／取消。

用户在查看旧记录时，不因保存反馈或新内容强行跳回顶部／底部。关闭详情返回原来的记录位置。成功提示短暂、局部且不过度重复，不常驻“本地记录共几条”等填充信息。

5.2 回忆：搜索条件可理解，出处可回去

媒体类型与收藏维度分开；筛选草稿与已应用条件分开，关闭不应用；重置筛选不清搜索词。界面应根据实际人物／标签／日期生成选项，不移植原型固定的 11 月日期和样例人物。[S04][S05]

已有“创建时间／事件时间”等日期语义如在原生支持，应通过适度展开保留，不能美化时强行合并。图片与音频并存的混合记录如何匹配类型必须有明确定义和测试，而非简单给每条记录一个演示 kind。

搜索工具栏稳定，焦点变化不移动用户正在点的按钮。筛选生效后只显示有用条件反馈；清空结果时提供保留搜索、调整筛选的路径。日期分组无可见记录时隐藏空组；返回后搜索词、筛选、滚动和选中记录保持一致。

原文摘要与 AI 回答在视觉、标签和来源结构上区分。没有可用模型时不得让“问一问”看似已具备语义答案能力；可保留配置／说明入口，但不生成演示答案冒充用户数据。

5.3 待办：日期、确认、完成、提醒各有语义

保留已改的今天标记／选中日区分与紧凑行高。周历之外有清楚的年月日上下文；跨月／跨年选择使用真实日历。单行任务紧凑，带时间／提醒／来源时自适应增高，不靠固定高度压字。

完成按钮只负责完成；标题区域进入详情／编辑。完成操作立即可感知，但只有实际提交成功才显示稳定完成态；失败回滚或明确提示，不能把失败任务从列表吞掉。需要撤销时使用可靠的状态操作，不靠延迟动画偷偷撤销真实提醒。

待确认草稿不计入正式待办，也不通过一次列表点击自动批准。确认页必须清楚展示任务标题、日期时间、来源和提醒选项。取消、完成、删除或改期后，相应系统调度应正确撤销／更新。

提醒信息保留“未安排／已安排／受权限限制／失败”等必要差异；铃铛仅作辅助，不承担所有状态。已安排不能写成已送达。

5.4 编辑面板：记录、任务和筛选不共享僵硬高度

记录编辑可有宽松正文区；任务标题默认较短并随内容增长，日期紧接内容；筛选按选项自然排列。三者共享顶部栏和操作等级，不共享一个巨大的固定文本框。

键盘、导航栏和系统手势区由实际 WindowInsets 驱动；不能复制原型手机框、模拟状态栏或底部横条。Compose Insets 消费规则需避免重复加底部 padding，输入区与面板实际验证 imePadding／安全区域行为。[R02]

面板拖动不是唯一关闭方式；长文本滚动不得误触为关闭。返回、关闭、点遮罩、拖动和系统手势的保存／取消语义保持一致，详见第 6 节。

每项先盘点当前入口、控制器和测试，再做样式迁移，不能按名称推定所有功能已经可用。

以下是必须实现／验证的行为契约；已存在的正确实现应复用。不要把原型内存变量直接当作原生持久化策略。

场景 进入／变更 退出／返回 失败／中断
新记录 创建独立草稿；附件复制与正文状态可追踪 关闭编辑保留约定的草稿，成功提交才清空 写入失败保留输入；进程恢复不得把未保存误报已保存

7. 组件、动效与噜噜的精修标准

7.1 统一性不等于所有容器长得一样

按钮分主操作、次操作、工具操作、破坏性操作；全局同语义同等级。每个面板通常一个完成性主操作。选中日期、选中主题和已完成任务使用各自明确的状态，不靠“都变成主色”混在一起。

图标使用同一网格与笔画体系，但允许光学校正；不要为大小一致把复杂图标压得看不清。导航标签始终可辨，选中底形可以小，点击区域不能随之缩小。状态图标应有可访问名称；装饰图标不重复朗读。

播放器减少“记录卡—内层卡—圆按钮”的层层厚底。波形只有确实来自素材或播放进度时才表达相应含义；没有提取波形时使用明确的进度条，不制造看似真实的波形证据。播放时长与记录时刻分开排，暂停／停止／重播的状态真实可辨，保留音频筛选。

7.2 动效建议：动作快，环境慢

下面是设计起点，不是已经测出的最优值或现有帧率结论。动画应可打断、可反向，不按每次点按排队播放。

场景 起点建议 验收方法
按压 按下 80–100 ms；释放 120–160 ms；小幅明暗或不超过约 2% 缩放 快速连点不延迟提交、不移动邻近布局
底栏切页 160–220 ms 淡变；小位移；选中底形连续移动 连续切换以最后操作为准；保留各页滚动状态
面板 进入 260–320 ms；退出 180–220 ms；拖动跟手 方向反转／中途取消不跳跃，内部滚动不误关闭
完成反馈 先显示提交／成功状态，再平滑调整条目 回滚、撤销和提醒状态与真实结果一致
主题切换 短交叉渐变；主内容位置不变 不出现白闪，不重置输入、不改变阅读位置
背景 长周期、低幅度；不让地平线明显移动 编辑／滚动／后台时暂停或降低；恢复连续而非从头闪动

减少动态开启时取消明显位移、弹性缩放、漂移和持续光效；必要反馈使用短淡变或立即切换。系统减少动态与应用设置共同决定实际播放状态，但不抹掉用户之前选择的背景模式。

三页切换不让每条记录单独依次飞入。避免边滚动边实时大面积模糊、闪烁高光或多层缩放。性能结果以实际可测构建和帧时间记录为准，不以视频观感或“平均 60 FPS”一句话代替。[R06]

7.3 噜噜：在内容边缘自然陪伴

正式美术仍未批准，不把现有文字占位、拒绝过的候选或网上素材当作授权成品。先通过 MascotAssetProvider 一类既有资源接口保留槽位与静态回退，不让角色资源影响记录主流程。[S02][S03][S09]

主页面只需小型入口，约 40–48 dp 可见形象配充分触区；不新增大型角色欢迎卡。主动点击时可做短暂眨眼、歪头或轻晃，记录实际保存成功后可短暂点头，不对每条记录弹陪聊气泡。

回忆与待办无需重复常驻一只。三主题通过接触阴影与轻微环境光协调，不把角色本色强行染成三套颜色。减少动态提供静态回应。角色不能读取记录、推断事实或触发任务，除非另有明确的功能设计和授权；本轮不新增这类能力。

8. 原生迁移策略：复用业务，替换表现，逐条保全

8.1 先建立路由与能力清单

Codex 在实际仓库中确认所有 Composable、导航、ViewModel、控制器、权限入口及测试路径。现有入口接线涉及记录、附件、原音、版本、来源、关键词、候选、正式待办、提醒、导出、回收站、记录包、回顾与应用访问等；接线只能证明存在，具体可用性逐项验收。[S01][S10]

输出 frontend-parity-map：每个旧入口对应新入口、当前状态、控制器、回归用例与截图。缺失项必须有“未迁移”标识，不能悄悄隐藏。高级功能可以渐进展开，但不能以简化 UI 为由删除仍在原始范围内的能力。

8.2 建议的最小迁移切片

先实现主题／表面／文字／按钮／图标／导航等原生基础，再迁移“此刻—打开编辑—保存—查看原文—返回”一条真实链路。该链路通过后迁移回忆，再迁移待办与二级流程。

所有组件从现有真实状态派生，事件交回既有业务接口。不要在新 Composable 中新建另一套永久记录列表、另一份提醒状态或另一套来源判定；不要把 HTML 的 state.added、固定日期、演示播放器等移入产品。

长篇入口文件可以做边界明确的组件提取，但不要把“全文件重构、数据库迁移、工具链升级、新主题接入”塞进一个提交。每次改变标明对应 D 阶段；跨阶段业务变更独立评审，遵守一批一验收。

8.3 实现参考而不是页面照抄

Android Compose 的可访问默认值用于触区、角色与语义；Insets 用于键盘和系统边界；WCAG 用于合成对比；Macrobenchmark 用于启动、滚动与交互性能验证。[R01][R02][R04][R05][R06]

这些参考解决交互和质量问题，不要求把 AIyou 改成标准白色 Material 模板。借鉴组件规则，不复制第三方品牌画面；Figma 可用于变量、组件变体、长文与错误态的对照板，不作为缺少原生验收的替代品。

9. 底层功能与产品闭环的未完成清单

这里区分“明确未启用”“已接线但未验收”和“仍需盘点”。除已取得日志的编译错误与恢复演练失败外，下面的风险场景不是已经复现的所有缺陷。

9.1 P0｜构建与来源引用基线（CORE-01）

复现第 2.2 节失败，定位当前实际文件和 allCitations 的定义／引用。最小修复后跑领域与引用相关测试，再按仓库规定执行实际 Android 检查。引用 ID、版本、来源撤回、删除与权限校验都不得被弱化。

退出标准： 新候选 SHA 的实际命令、非零测试 XML、失败／跳过数、日志与构建结果可复查。无法取得 SDK 或工具环境时分别标记阻塞，继续可执行的纯 Kotlin／静态任务，但不能把整批标成通过。

9.2 P0｜记录、附件与加密存储可靠性（CORE-02）

已有本地记录链路并不免除以下验收：保存事务与附件复制的先后边界，磁盘满／撤权／进程终止，草稿恢复，原文新版本与派生内容失效，数据库版本迁移及 SQLCipher 原生执行。

普通文本保存、图片复制、音频存档分开记录成功条件；部分附件失败时不应丢掉已写正文，也不应误报完整保存。明确错误恢复路径，不通过一直转圈掩盖失败。采用合成数据，不用用户真实库做破坏性试验。

退出标准： 原始方案要求至少 100 次模拟进程终止／重启场景，已显示成功的记录不丢失、附件完整性可验证；仍需声明这些场景覆盖范围，不能据此宣称绝对不丢数据。[S02]

9.3 P0｜备份恢复与删除传播（CORE-03）

README 保留的 D08 演练 40473284135 在探针 admission 阶段失败，未进入实际备份恢复；首因未定位，临时 KVM ACL 的精确恢复也未确认。新诊断“编译过”不能改写为“演练成功”。[S01]

先定位 admission 与环境边界，不自动更改未知 KVM 权限、不清未知锁、不终止未知进程。在明确授权的可丢弃测试环境中执行：保存合成原文和附件→导出／备份→全新安装→恢复→查到原文／附件／版本→重新配置不应随包导出的秘密→检查提醒处置。

加入错误口令、损坏包、版本不兼容、可用空间不足、用户取消、进程终止、重复恢复、选择文件权限变化。确认失败恢复的回滚／保留规则，不要求所有失败都“自动重试”。删除传播需覆盖索引、来源片段、派生事实、候选、提醒、缓存和恢复旧备份后的策略，防止已删除内容无提示复现。

退出标准： 新装恢复有实际设备执行证据；明文导出风险清楚；删除／恢复不破坏未选中数据；环境清理有精确记录。未跑到恢复步骤必须报告未跑到，而不是记录恢复失败或成功。

9.4 P0｜隐私、锁与授权所有权（CORE-04）

默认 LOCAL_ONLY 保持。新主题、搜索、详情和预览缓存不能绕过应用锁、来源授权、导航会话和删除失效边界。验证后台／锁屏／最近任务画面、崩溃日志与报告附件是否暴露私密内容；UI 状态恢复不能泄露搜索词或密钥。

外发策略、供应商、用途、记录版本或可用来源变化后，旧的授权／异步回调不能继续写入或展示不该显示的内容。媒体权限只在需要时申请，拒绝权限仍能做纯文字记录。

退出标准： 禁止外发内容、秘密、已删除／已撤权材料不出现在测试请求和日志；锁与生命周期的关键设备路径通过。对“已构建 APK 无 INTERNET”的历史事实在新 APK 上重新核验，不能凭源 Manifest 片段断言最终包权限。[S01][S02]

9.5 P0｜真实提醒闭环（CORE-05）

待办与提醒有本地路径，尚不能据此证明不同厂商按时送达。测试通知与精确闹钟相关能力／权限、拒绝与撤销、Doze、重启、时区和时间改变，以及任务改期／取消／完成／删除。

时间含义和“精确／大约”应如实表达；提醒送达与调度登记分开。恢复备份后如何处置过期与未来提醒须明确，避免重复或未经确认新建系统行动。

退出标准： 选定设备矩阵中按步骤记录实际调度、通知与导航结果；对于系统限制说明可见，未送达不显示已送达。不得仅以调用调度 API 成功验收。

9.6 P1｜媒体采集、OCR 与 ASR（CORE-06）

三项分别验收，不能把人工录入等同自动识别：

  • 原始媒体： 现有受控 PCM 路径不代表已支持任意音频格式或所有麦克风。盘点实际编码／容器、导入、录音、播放、音频焦点、路线切换、权限与中断；不支持的格式给明确反馈，不能静默失败。
  • OCR： 现有图片文字来源纠正／检索不等于能对新图提取。确认本地或用户授权远端的提取方案、语言与限制，接入前呈现“不可用／未配置”；图片本身始终可保存、查看。[S01]
  • ASR： 原音保存与人工转写是可用的降级路径；自动 ASR 未启用。按运行时实际能力决定是否提供识别，不能承诺每台机器都有离线中文服务。服务不可用、无权限、转写失败时保留原音。[S01][S02]

退出标准： 每种能力有真实支持范围、成功／不可用／失败／取消状态；来源时间段与修改版本可追溯。新增供应商、SDK、网络能力或相关协议需要独立核验和已有明确授权，不能借 UI 迁移偷偷引入。

9.7 P1｜模型配置、真实整理与出处问答（CORE-07）

两类兼容协议、模型 ID、SSE、连接配置和来源规则的代码／Mock 契约，不代表真实模型链路已启用。保持现有协议抽象，不擅自新建 AIyou 服务端。[S01][S02]

先离线补足契约：正确端点与错误响应、流中断、取消、超时、结构化输出无效、能力不支持、秘密不入日志、旧版本／旧授权结果拒收、重复响应去重。随后仅在有明确批准的连接与合成数据上做真实调用；无授权时完成离线工作并保留阻塞，不自行设置密钥或开启网络。

AI 输出与原文分离；模型建议只生成候选，用户确认前不能写入正式任务或稳定事实。问答逐条论断核验引用来源与版本；没有证据时明确无法回答，不用检索分数当事实置信度。

退出标准： 两协议契约恢复绿色；真实链路及质量记录单独存在。原方案的至少 100 条质量样本、引用 ID／版本有效率 100%、人工支持率目标 ≥95%、Recall@5 调优目标 ≥85%均按实际样本量与统计口径报告，不把这些数字写成目前已达到的结果。[S02]

9.8 P1｜回顾与其他待盘点路径（CORE-08）

核查日／周回顾当前是否仅有确定性事实汇总、是否有真实 AI 回顾，以及入口、日期范围、引用、空状态、取消和保存结果。不得仅因 FactRecap 一类命名出现就勾选“AI 回顾完成”。

同样盘点原始设计书中的模型用途分配、能力限制、存储与用量、应用锁、处理范围、许可证等页面：已有的保留与完善，缺失的单列，不用一页“更多”文字清单代替真实入口。

退出标准： 需求—实现—入口—证据矩阵不再有未解释空白；确实不在当前发行范围的项有明确范围决策，而不是笼统 TODO。

9.9 本地预览与完整 v0.1 的两道门

新版原生本地预览可先交付： 前提是现有核心本地能力不回退，关键保存／隐私／恢复风险有明确处置，界面不暗示尚未启用的模型、OCR、ASR已经可用，并完整披露设备未验范围。

完整原始 v0.1 不可仅靠前端签收： 原方案要求的模型配置、整理、出处问答等必须完成相应验收，或由用户明确批准重新定义发行范围。不能由 Codex自行把原始功能删掉后宣称“全部完成”。ASR的“有可用能力时转写”与无服务时保留原音，应按原始条件式承诺验收，而不是强求所有设备都具备离线识别。[S02]

11. 全面完成的定义

11.1 前端完成门槛

三主页、核心二级页面和设置使用同一套原生主题／组件；最新原型认可的改进都已落地；无演示数据或假播放器进入真实路径；原有功能入口完整保全；正常／空／加载／失败／拒权／禁用／成功等状态可辨；中文大字与窄屏可用；对比、触区、TalkBack、键盘和返回流程有证据；背景可关闭／减少且性能可接受。

“把三张首页变好看”不是前端全部完成。没有真机或必要辅助技术验证时，只能称原生实现与相应自动化完成，不能称整体体验验收完成。

11.2 产品与底层完成门槛

当前候选构建与测试通过；保存和附件可靠性达标；数据库迁移与原生加密执行有证据；新装恢复、删除传播、隐私与提醒关键路径闭合；原始 v0.1 承诺的模型／整理／检索问答等完成或由用户明确批准范围调整。任何依赖授权或能力条件的项都如实披露。

11.3 发布前仍需独立关口

本计划不授权发布、替换签名、自动安装SDK或接受协议、使用真实密钥、开启付费模型、迁移真实用户库、修改生产云服务。预览APK与正式发布资格分开；正式签名、素材许可、商店要求等保留人工审批，不用本计划充当许可文件。[S03]

12.2 每批交付的最小粒度

一个提交／PR聚焦一条纵向闭环或一组基础组件，包含相应测试与证据。建议首次只执行 G0：盘点＋构建最小修复，不顺手全面改 UI；第二次再执行 G1。后续按依赖推进，每次保留明确回退点。

UI 修改涉及新数据库行为或权限策略时拆出底层任务，不将其混进视觉PR。失败项先记录并定位，不以删除用例、放宽校验、更新全部截图基线或大规模升级依赖掩盖。
