# 正式本机页面：输入反馈与布局

这组改动以 `f02fa0529dbfa3985641288e4e35631f2e7c5061` 为基线，只处理正式本机页面与共用的不可用搜索提示。原始两份方案保持不变。

## 问题和行为

- 正式 `LocalRecordsScreen` 没有示例 `MainScreen` 的居中 720dp 宽度上限。现在正式此刻、回忆使用同样的约束；窄屏大字体的摘要自然换行。
- 超过既有 `100000` 长度上限的编辑原先直接返回，没有反馈。现在整次拒绝并保留先前草稿，显示明确提示；下次有效编辑清除提示。限制仍是 Kotlin String 的 UTF-16 长度，并非可见字素数，不截断或改变存储限制。
- 存储失败原先还会将输入框标记为“输入需要处理”。现在存储错误和输入拒绝分别呈现；错误/保存反馈位于输入后方，实际重试操作位于错误卡片内。保存成功仍只能来自原有事务与读取回验，不因这组 UI 改动提前显示。
- 正式输入区域只显示已开放的保存操作，未开放的提问、图片、录音以说明呈现。共用搜索/筛选说明合并为一个区域，保留真实禁用语义，无搜索或筛选行为。

输入项在基线已有 `composer` 稳定 key；本次不把缺少 key 或已发生焦点丢失当作已确认缺陷。

## 回归与渲染要求

`checks/record-queue` 编译实际 ViewModel 源码。新增测试覆盖 99999+2 的拒绝、100000 的接受、100001 的空草稿粘贴、恢复编辑及补充平面字符；原三个队列故障测试保留。该主机假持久化边界不是 Room、SQLCipher 或 Keystore 设备验收。

`LocalRecordsPresentationTest` 使用真实 AIyouApp 本机路由与合成状态，覆盖宽屏居中、存储错误分类与重试、待确认保存锁定、输入反馈清除/焦点，以及 320dp/200% 字体时保存可达。它是 Robolectric Compose 交互回归，不等同于实际输入法或 TalkBack。

后续补充两项独立失败态回归：320dp/200% 字号下，保存失败与读取失败的重试操作在首屏未完整显示，必须滚动到真实按钮，验证全部按钮边界位于屏幕内、按钮语义/启用状态、语义请求键盘焦点和点击各自重试回调。禁用输入不获取焦点、不调用编辑/保存，滚动和重试后的合成 loading 状态保持原草稿与待确认提交标志，不提前显示保存成功。读取失败使用合成已知文本检验呈现保留，不声称数据库恢复或 ViewModel 重试逻辑通过该测试。Compose JVM 总数由11增至13，真实XML门槛同步提高；结果检查还要求这两个具体类/方法各有唯一通过的实际XML用例，并打印其名称，不能用其他用例补足总数。首屏断言仅证明按钮未完全可见或未组成，不证明零像素可见。

按钮焦点检查在触摸之后明确请求并确认 JVM 平台的 `Keyboard` 输入模式，再请求按钮焦点并断言成功；不依赖默认输入模式，也不把这当作实体键盘或 Tab 顺序验证。原编译失败的两处导入已修正，实际失败日志单独保全，未把未执行的焦点断言当失败原因。

现有静态 Preview 渲染无法执行滚动交互；248张图保留原首屏状态，不把首屏截图称为滚动到重试按钮后的截图。滚动后像素截图未生成；本次滚动可达与焦点结论仅来自上述真实组件的 JVM 交互断言，设备输入法/TalkBack仍需实际验证。

新增 32 个生产渲染用例：空记录、恢复草稿、保存中、保存失败、读取失败、保存成功、超限拒绝与回忆，分别采用 360dp、320dp/200%、800dp 横屏、840dp 大屏。直接调用生产本机路由，不开启 `previewDemo`，没有数据库/模型调用。原 216 个用例保留，总数 248。PNG 原样放入既有 `aiyou-white-blue-pages` 小包，不增加 workflow、权限或上传 artifact 数量。

沿用现有 `.github/workflows/android.yml`：真实 metadata、APK、Compose JVM 测试、严格 lint、生成/验证渲染及结果检查均须通过。更新初始 smoke references 不是批准 golden；视觉验收需要实际看图。当前实例未配置 SDK 的失败日志保留，不重新运行同一 Android 失败命令、不安装 SDK 或接受新协议。检查结果、精确源码 SHA 与证据在本轮独立交付记录中报告。
