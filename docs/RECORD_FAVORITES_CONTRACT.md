# 记录收藏完整功能批

基线为永久删除封存源码 `7a6d203c056c8a35305ad48903aed690eae45b60`。
对应两份原方案的 F02、回忆页收藏筛选；收藏的是已保存的记录身份，
不会把聊天、AI 输出或标签变成原文。原方案保持不变。

## 用户流程

原文页显式收藏或取消收藏；回忆页选择全部或仅收藏，并可继续组合关键词、
日期和手工标签查找、打开原文。取消后离开收藏结果，冷重开仍按实际已提交
状态展示。移入回收站时隐藏收藏，恢复后重新可见；永久删除同时移除收藏。
编辑原文保留记录身份的收藏。现有 v1 原文/标签包不包含收藏，恢复的新副本
初始未收藏；不扩大既有包和开放导出的格式范围。

## 数据与写入边界

使用现有 SQLCipher records owner 的 entries 元数据，不引入独立文件、密钥、
网络、权限或数据库生命周期。Room 8→9 加法迁移只向 entries 添加收藏布尔、
独立版次、最近 mutation ID 和该意图的原文版次，旧原文/修订/草稿/附件等不改。
旧 2..8 schema 与 native assets 保留；Room9 必须来自真实 KSP，不能手写导出。

写入是明确 set/unset，绑定 entry ID、所见原文版次及哈希、来源 generation、所见收藏版次、目标值、
稳定 mutation ID；独立事务内检验当前来源、回收/永久删除 fence 和收藏 CAS。
同一未决意图重试只确认最近已提交回执，不再次翻转；原文已编辑时，同一已
提交回执仍可确认该记录的收藏，但新意图须绑定当前原文。另一收藏意图已提交
后，旧版次冲突，不能覆写新选择。失败/丢回执不显示乐观成功或虚假空列表。

收藏列随 entries 删除而移除；现有永久删除 DONE 的 entries absence 验证
涵盖收藏值和最小回执，不建立可遗留的旁表。收藏保存在加密数据库内；主机
SQLite 合成 fixture 的行为证明不等于 Android SQLCipher 加密/重启证明。

## 查询与界面边界

仅收藏条件进入真实候选查询，在分页、扫描和候选上限之前执行；不在已有
截断结果上再做界面过滤。收藏变更递增实际查询 epoch，使旧 READY/proof、
打开回调失效。原文/标签未变时不重做 tokenizer/body；原有来源变更仍正常
失效索引。输入与当前来源的实际 CAS 保留，已退役/旧按钮不能改写新选择。
元数据按最多256行的keyset页校验，独立上限65536行；达到上限仍需读取一行
以判定是否超限，超限失败，不截断为已就绪或空收藏。查询proof只持有实际
候选的收藏快照，最多沿用1000候选预算。此元数据校验会读取非收藏行，
不能将仅收藏查询描述为“只扫描收藏”；原文扫描预算在收藏过滤后计算。

读取失败、保存中、未确认、冲突、空收藏/无匹配均有可操作反馈。当前页仅
保存公共筛选布尔；原文、搜索文字、收藏 mutation 等私有 payload 不进
SavedState、日志或通知。按现有 48dp、200%字体和窄屏规则做 Compose 验证。

## 来源代次修复（2026-10-17）

从已独审的 `246bf214cfeec44226c87ea3e700c45f54d5df8e` 接续。普通同一队列按 FIFO 执行，旧导航按钮也有失效保护；不能仅凭直接SQL探针声称用户操作必然交错。实际可达路径是：收藏先在提交前失败，未确认意图保留；用户通过实际回收站移入、恢复，再在恢复记录页点击“重试确认收藏”，旧意图可能首次落库。另有实际控制器排队、独立SQL所有者在首次SQL调用前删除恢复的受控路径。原文版本与哈希、收藏版本均未变化，来源 generation 已1→3。
