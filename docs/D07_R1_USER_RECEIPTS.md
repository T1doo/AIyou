# D07 R1：系统进度不覆盖用户请求回执

父侧已准入R1方向；本片只实现持久回执前置，不接AlarmManager／通知，不申请权限，
不宣称完成D07系统提醒。R2的PENDING唯一触发、锁态token及外部调用执行门仍待设计独审。

## 行为变化

确认已提交但UI未获ACK后，即使系统ACK或已核对触发已经推进数据库状态，
同一不可变用户请求仍可读取当前认证快照，不再把自己的已提交操作误判为版本冲突。
该重放是只读：不重新确认、不改回PENDING、不再安排、不重加代次或重写密文。
新用户操作仍执行原CAS；后续用户决定退休旧回执，旧请求不能越过它。

`ManualTaskCipher.UserReceipt`在任务v5密文中保存最近一次用户请求的task ID、操作、
mutation ID、expectedVersion、请求时间、完整规范化请求摘要和已提交用户决定的摘要。

| 请求 | 额外绑定的全部输入 |
| --- | --- |
| CREATE | 标题、创建时间／时区、日期／时刻／IANA时区／偏移及来源创建回执 |
| STATUS | 目标完成／取消状态 |
| RENAME | 规范化标题 |
| SET／POSTPONE／CLEAR | 操作、完整目标日期／时刻／时区／偏移或明确清除 |
| REMIND | 完整旧任务快照，包括来源回执和旧提醒／命令；精确／大约或明确撤销 |

每种摘要还绑定任务ID、操作、mutation ID、expectedVersion和请求时间；CREATE没有调用者
expectedVersion，固定为0。REMIND保留旧完整请求摘要并加上明确操作命名空间。
不同字段／操作不是同一请求，即使mutation ID相同也拒绝。

用户决定摘要绑定任务身份、标题、状态、创建信息、日期、来源回执及提醒身份／模式／时间与撤销决定。
系统行版本、检查时间、调度阶段及outbox进度不冒充新的用户决定。
RM_ACK／RM_FIRE只保留已认证回执；不接受系统调用者传入另一份用户决定。
修改／提醒重放、迟到ACK及触发不UPSERT缺失目标；CREATE沿用既有显式新建合同，
本片不新增正式任务硬删除路径。

## 格式与旧数据

沿用manual_tasks表、已有purpose密钥、随机nonce和AES-GCM framing；不迁Room、不新增alias／依赖。
新用户写采用有界v5（最多65536字节），AAD仍绑定格式、task ID、行版本和最新物理mutation ID。
回执字段有长度、枚举、版本、时间和用户决定绑定检查；不支持格式、认证失败、错误AAD和尾随字节拒绝。

v1–v4保持原解码／AAD，读取不重写；明确用户修改才写v5。旧格式最新操作仍是可证明的用户操作时，
首次系统写可认证并携带该回执。若旧格式已经丢失历史用户回执，不从RM_ACK／RM_FIRE猜造历史。
v5向后读旧数据；不承诺旧二进制读取新v5。

普通新写的格式断言由2／3／4改为5，旧v1独立字节、v2／v3直接密文和v4系统推进均另有真实回归。
“不支持格式”断言移到v6；旧支持格式的AAD篡改与EOF断言保留。未删业务断言或放宽认证。

## UI与备份边界

实际TaskReminderController在读回失败后保留原request对象；外部受控driver提交系统ACK后，
重试仍使用同一对象并展示当前持久快照，清除pending，不新建计划、不再调用schedule。
回执不进入UI模型、Intent或SavedState，toString脱敏。

完整离线备份在新key恢复时清除可执行用户回执，提醒仍为REVOKED且无命令；
旧确认不能通过恢复重新安排。原有来源／提案不可变创建回执和已确认任务仍保留，
其只读去重不等于获得提醒执行资格。开放选定包继续排除设备执行状态。
