# §8.2 事件日期补记与检索

原始 `AIyou_Master_Plan.md` 与 `AIyou_Product_Architecture.docx` 保持原件。
本轮从 `aad78720685aa9c001d27ea8573cd3557dfc4d91` 接续，处理两份原方案 §8.2
中事件发生日期与捕获时间的分离；不是相对日期推断或事件自动抽取。

## 已实现语义

- 仅接受用户手填的有效单日 `YYYY-MM-DD`（0001–9999）与 IANA 时区标识，
  例如 `Asia/Shanghai` 或 `Etc/UTC`。不接受“昨天”、范围、时刻、仅偏移量或未知时区。
  不将全天事件转成某个时刻；即使某地区历史上跳过该民用日，原填日期也原样保存。
- 设定、纠正与清除均先展示原值、新值和不改原文的范围，再单独确认。未补记保持
  unknown；明确清除后保留递增版本和请求回执，两者不混作一次用户操作。
- 元数据与请求回执由同一 SQLCipher records owner、排空 lease 和事务保存。
  原文版本/hash 与元数据版本共同 CAS；同一未知提交重试原请求，旧回执不得覆盖
  后来人工改值。关闭再打开读取持久真值，缺损元数据整体报错，不用捕获时间兜底。
- 检索显式区分“记录日期”和“事件日期”。前者保持原捕获 instant 按记录保存 IANA
  时区取日；后者比较已填写的日历日，不随设备时区变化，未知不匹配事件日期。
  两种日期口径都可与关键词／精确原文、手工标签和收藏做 AND 组合。事件元数据
  变化使旧检索快照失效，不重写正文索引、原文、捕获时间、标签或授权。
- 回收站隐藏事件元数据及其检索成员；恢复仍保留用户补记；永久删除通过源外键
  级联清除本机事件字段和请求回执。外部已导出文件仍由用户控制。

## 导出、恢复与回顾兼容

当前原文 Markdown、JSONL、图文 ZIP 明确携带事件日期和 IANA 时区，预览后若值
发生变化必须重新预览。带事件值的独立口令包使用新认证版本 `AIYOUPK5`，可与完整
原文历史和正式任务／DRAFT 范围组合；日期字段受认证和摘要约束。无事件值仍使用
既有包版本；v1–v4 仍可读，旧包中的事件日期为 unknown，不从原文或捕获时间推断。
恢复只在首次建立新 ID 副本时写事件值；同包重放不重置后来人工纠正／清除。
加密包迁移的是当前日期值，不迁移事件元数据的修改历史、源版本或操作回执；
unknown 与已清除的空值在新副本中都表示未补记。开放导出另附源 `eventDateVersion`
供检查，也不承诺将它作为目标库请求回执恢复。
捕获时间、原文历史、原图加密和删除回执仍沿用既有合同。恢复不重连密钥、不恢复
联网授权、不创建原生提醒，仍不是全库备份或完整迁移。

现有本机日／周回顾仍按捕获时间和回顾时区归日，并在界面说明事件补记不会改变
回顾分组。需要按事件日找回原文时使用“事件日期”检索；未增加事件日回顾或 AI 叙事。
