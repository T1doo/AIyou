# Original-plan source audit and selected D05 recovery slice

Baseline: `cc9ef4d22f4a433bf9f83297265677601c2fcbc5`. Both original `AIyou_Master_Plan.md` and all DOCX paragraphs were read; neither was edited. This is a source audit, not milestone or device acceptance.

| Scope | Existing product implementation | Specific remaining scope and decision |
| --- | --- | --- |
| D03 / §12 | `MixedCaptureScreen` + `MixedCaptureController`, `LocalAttachmentScreen` + encrypted attachment store: local JPEG/PNG capture, drafts, current-version reading; `JpegPayloadValidator` and `PlatformImageDecoder` handle bounded decode/orientation. | `CaptureDraft` supports images only. Short recording/ASR and OCR are absent, not merely awaiting device acceptance. Recording needs a separately implemented microphone lifecycle/permission path; bundled OCR needs a model/dependency decision. Neither is added in this slice. |
| D04 / §11 | Protocol request/SSE adapters, `OkHttpStreamingTransport`, fixed-sample capability exchange, encrypted connection/secret/capability stores and explicit reviews exist. | Production `LocalRecordsViewModel` leaves `bindAi` and `capabilityProbe` null; manifest removes INTERNET. Real service activation remains a separate network/credential decision. Existing local configuration and Mock contracts are independently implemented, not blocked by that decision. |
| D05 / §§9.2–9.3,10.2 | `LocalCandidateController`/dialog and `SqlLocalCandidateRepository` implement local literal excerpts, authenticated source checks, persistence and explicit review. | At baseline close/dispose cancelled the producer, reopening only read RUNNING, and UI offered cancellation/regeneration. Selected slice: explicit recovery of the existing same batch, with a non-creating authenticated resume read, exact completion receipt retry, one producer slot per controller and stale-callback fences. The original plan supports durable recovery; it does not require this exact same-batch UI design. |
| D07 / §§5.3,13 | `ManualTaskController`, `ManualTasksScreen`, `SourceTaskController`, `TaskProposalController` and SQL implement explicit manual/proposal confirmation, dates/time zones, changes, postponement, completion/cancellation and durable reminder commands. | `TaskReminderController` deliberately uses `DisconnectedReminderDriver`; no AlarmManager/notification receiver is bound. System scheduling/permission and reboot integration remain real implementation work, while local task flows already work independently. No notification/alarm permissions or stub-success claims are added here. |

The selected recovery uses the existing schema, key purpose, source generation and completion CAS. It does not enable a model, infer facts, accept candidates, create tasks, change LOCAL_ONLY, or add dependencies/permissions. Host SQL cold reopen and coroutine/controller tests do not prove Android process recovery; Compose JVM tests do not prove physical-device interaction. Complete D03/D04/D05/D07 acceptance remains separately scoped.
