# D06 统一五类关键词找回：捕获日期范围设计

基线 `9a581348555bcc9ab1d2fe1f600d7f37a7625b8f`；本候选只有设计，未实施／验收。
遵循两份原方案 §5.2、§8、§10.3–10.4；原方案不改。延续现有五类逐字检索，
不实现自然语言时间、事件日期、语义检索或完整 D06；LOCAL_ONLY，无新 SDK／权限／模型。

## 1. 已有合同与最小用户闭环

原文高级搜索已有 `LocalSearchRequest.from/through`，CAPTURED 路径用
`Instant(capturedAtMillis).atZone(captureTimeZone).toLocalDate()`，两端日历日包含。
统一入口尚无日期输入；`SqlUnifiedKeywordRepository` 仅按关键词／类型聚合。
本片在该入口增加两个纵排、全宽日期输入和“不限日期”，主动查找后统一过滤五类结果。
标注“捕获日期 · 按每条记录保存的时区；不是事件发生日期”。不自动检索、不新增存储入口。

## 2. 时区、边界与无效输入

- 起始／结束日期是既有四位 ISO 日历日期 `YYYY-MM-DD`；严格正则和 LocalDate 校验，
  不裁切空格、不补零、不解析“上周”，不做宽松归一化。复用现有日期解析合同
  （四位年 0000..9999），不另加相对今天的年限；合法未来日期可得到真实空结果。
- 两端都空＝不限；只填一端＝单边范围；起止同日＝该整天；起始晚于结束＝无效。
  空是精确空串，空白、半成品、非法闰日、控制符及不完整字符不当成“不限”。
- 每条来源以其保存的 IANA `captureTimeZone` 计算捕获日，不用手机当前时区、UTC 截日，
  也不把所有记录改用一个查询时区。改变系统时区／时钟不改变相同请求的成员资格。
- 日历语义 `from <= capturedLocalDate <= through`；等价时间区间为每条来源时区下
  `[from.atStartOfDay(zone), through.plusDays(1).atStartOfDay(zone))`，缺端无限。
  实施优先比较 LocalDate，避免结束日+24小时／末毫秒技巧或上界运算溢出。
  夏令时 23／25 小时日按真实时区规则；整天被跳过的日历日不会伪造捕获时刻。
- 来源时区／捕获元数据损坏按既有认证失败处理，不回退手机时区或把坏来源说成无命中。
  记录本身的合法时间域不因输入格式而改变；两端空仍覆盖原有合法记录。

## 3. 日期从哪里来、如何呈现

五类都用当前原件认证后的 `binding.captured/zone`；原音／图片使用其精确原件绑定，
不是附件落盘日、转写／OCR／纠正日、偏好／线索创建或采纳日，也不是人工事件日期。
同原件的五类证据共同入选或排除，字段命中规则和 O/A/I/P/M 身份不改。
组头明确显示“捕获日期：日期 · 保存时区”，并保留原件版本，避免把 UTC 排序理解为当地日分组。
保持 captured 时间戳降序／sourceId 升序、组内证据键排序；不按用户当前时区重排。
日期过滤不改变类型自身的隐私资格，尤其不统一放宽派生内容的 AI_NONE／删除失效规则，
也不借此收紧原本允许找回的手工原文。范围不是授权或备份隔离机制。

## 4. 同一请求、联合认证与容量

domain 增加不可变捕获日期范围值；关键词、类型、范围构成同一查询请求／proof。
构造值同样校验日期域与顺序，不能绕过 UI 注入非法范围；snapshot 提供只读范围，
controller 在发布前核返回的关键词／类型／范围等于本次提交，不能只把未认证日期贴在 UI 上。
原有不带范围调用保持“不限”，新增带范围调用若旧端口不支持必须明确失败，
不得默认转成不带范围调用、忽略范围或返回假空。生产 SQL owner 必须真正实现范围。

- 原文将范围传入现有 `LocalSearchRequest(from,through,dateBasis=CAPTURED)`，
  保留既有 FTS 超集、逐字核验、1000候选／10000扫描等预算和 epoch 最终校验。
  日期仍在原文正文加载／候选预算前筛选；不先取得全库前1000再按日期过滤。
- 原音文字／图片文字／普通偏好保留现有完整集合、媒体／AEAD／图认证和全源证明，
  其128等既有保存／集合容量不变。最终共同事务用认证后的来源 binding 过滤证据，
  不把“只读取一个既有20条页面再过滤”当作完整结果；不以范围绕过原有集合限制。
- profile2 仍按 BINARY id、每批20 metadata 认证完整合格集合及历史，包括日期外、
  未命中及未采纳行；滚动回执覆盖全部资格行／元数据／epoch。
  只有“当前 ACCEPTED 且字段逐字命中且捕获日在范围内”才累加1000匹配预算并保留投影；
  日期外1001个文本命中不能挤掉范围内唯一匹配，范围内1001命中仍整组失败。
  不增加全库扫描／保存上限；复用每源20 READY检查和既有有界缓冲。
- 最后共同 SQL 事务核所有集合、当前原件真实 hash／捕获时间／保存时区／generation／
  政策和范围一致，确认提交 ACK 后才发布完整结果。范围内外变动、空变非空、非匹配行变化、
  损坏及丢 ACK 沿原合同拒绝；不得先发布过滤后的部分项或先导航。
- 日期元数据变更会触发现有 entries 搜索 epoch／来源 generation；不新增 schema、
  索引、迁移或备份格式。媒体与派生集合的范围外损坏仍按原完整认证边界失败；
  原文复用现有日期候选域，不额外承诺认证所有范围外正文。原文扫描上限不因范围窄而取消。

## 5. 编辑、生命周期、分页与回原件

两个日期输入保留编辑原串但不保存到 Bundle／SavedState／日志／磁盘。任一字段改变即
request++、清 proof／旧内容／错误并回第一页，不自动 IO；无效提交展示具体日期错误且零查询。
关键词空白而范围有效仍只提示输入关键词，不扩成日期浏览全库；无效范围先报错，不查库。
“不限日期”只清日期并使旧请求失效，保留关键词／类型；“清空查询和结果”清关键词和日期，
类型保持，回输入提示。合法完整查询确认后才可显示无结果，并提供修改／清日期入口。

捕获规范范围一次，私有 proof／分页／resolve／confirmed returnSeed 都带同一不可变范围。
翻页前完整复核，再按全部过滤结果每页20组；不拿页码／旧 cursor 套新范围。
返回原件后重新查同一关键词／类型／日期、第一页，不能复用旧 proof；退休清 seed。
范围 A→B→A 仍用独立 request，旧完成、旧页、旧点击／关闭／返回不能恢复内容或清新会话。
保留已审 navigation→lifecycle 仲裁、提交 ACK 和 admit 后不用旧 UI 自拒的边界；
逐行 guard 仍只读常量大小 owner/session/request/lifetime，日期解析与全来源检查不得塞进去。
有日期限制时，已观察任一来源修订／日期时区／政策／删除／generation变化退休整个查询，
所有 scope 都适用，不能仍仅依赖现有 `memorySelected` 或旧 proof 已保留的命中 bindings；
覆盖范围外来源新进入及空集合。observeRetirement 捕获该次范围与代次，不限日期保留原策略。
实际 SQL 取消释放后才承认结束，不用协程取消代替资源 ACK。

精确原文／原音／原图动作不重写日期、正文或派生文字，不新建任务或自动播放／推断。
QUOTE／NOTE 分离及 note-only 回跳真实依据范围不变；长文240码点摘录／高亮不改。
日期输入用短标签“起始日期（含）／结束日期（含）”，共享格式说明；全宽纵排沿既有主题、
48dp焦点样式与 LazyColumn。错误／清日期／查找／下一页／原件入口在200%窄屏横屏可滚动可达。
