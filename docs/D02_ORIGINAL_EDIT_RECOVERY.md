# D02 独立原文编辑草稿恢复

依据原 Master Plan F01/F02、§5.4、§8.2、§17 的草稿、原文版本及重启恢复要求，补齐此前 `ORIGINAL_EDIT_UI_REVIEW.md` 明示的“编辑修改只在当前应用会话保留”缺口。两份原始方案保持原字节。本切片不宣告完整 D02 验收。

## 保存与恢复

正式原文仍在既有 Room/SQLCipher 中，由 `revise` 的原子事务追加不可变版本、索引作业与当前版本指针。此刻新建草稿仍使用原 `capture_draft`。编辑草稿使用独立 UUID、源记录 ID、预期原文版本、历史来源版本、已确认草稿版本与输入，不消费此刻草稿，不直接改正式原文。

`EncryptedOriginalEditStore` 是生产适配器，使用平台 AES-256-GCM、每次随机 96-bit nonce、128-bit tag、版本与文件名 AAD。UTF-16 code unit 编码完整保留 IME 未完成代理字符，两个文本各限 100000 个 code unit；密文包总长有界。文件名为源 ID 的 SHA-256，不含原文。正式生产工厂通过 Android Keystore 包装独立随机编辑 key，使用独立 key 文件与用途 AAD；缺 key/错误 key/坏密文不生成替代数据。测试工厂的确定性 key 仅用于合成测试。

草稿位于 `noBackupFilesDir/records/records.db.original-edits/`；只有密文进入临时文件。每次操作确认已知父目录 entry 同步，只创建自有单层目录；父目录不可用不创建未知祖先。文件 fsync 后同目录 atomic rename，再目录 fsync，完成后才显示“已加密保存在本机”。文件与数据库不是一个事务：新版本已提交但草稿收尾/读取失败时，同会话只重试收尾与读取。正式事务已返回后若草稿 CAS 被竞争者改变，保留竞争草稿、刷新恢复索引，并独立核对已提交原文后完成本会话，明确提示另一个草稿待处理；不重复追加版本。若在二者间进程终止，重开保留 ACTIVE 草稿并显示源版本冲突，拒绝再提交旧基准版本；不自动推断其已被用户丢弃，不自动再次生成版本。

每个源 ID 的密文保存完整已确认身份/版本；自有非阻塞文件锁协调实例，写入比较完整旧快照。读取确认丢失后核对确切尝试快照，通过生产 store 的幂等目录同步再次确认后才采纳，可继续保存用户纠正；与其他写入者不同则保留当前输入、拒绝覆盖。丢弃也先核对自己已发布但未确认的确切快照，避免首次写入确认丢失后恢复已丢弃输入。明确丢弃写入清空文本的 DISCARDED 加密终止标记；正式提交成功后写 COMMITTED 标记。旧身份/版本的迟到写入不能复活终止草稿。用户明确开启新编辑使用新 UUID，不复用已终止身份。

启动只把可恢复草稿 ID/源版本放进列表，不自动导航或生成正式原文。用户点击“恢复编辑草稿”后验证源存在、仍为当前实现支持的 LOCAL_ONLY、基准与历史来源版本存在、基准原文吻合、读取期间源未变化。源版本冲突/源记录不可用时，仍展示并保留用户修改，禁止保存新版本，可明确复制输入或丢弃。每次自动保存重新检查源是否仍可用，源删除/不再支持时不写回或另造源记录。D08 的 tombstone、永久删除传播尚未实现，本切片不冒称已完成它。

已有草稿从历史页面被发现时，先恢复原有修改；历史文本不会无确认覆盖它。当前正在编辑的脏输入必须先经过既有明确替换确认。取消与系统 Back 沿用既有脏输入确认；丢弃未持久化完成时不关闭编辑，不假称已删除。并发草稿冲突后明确放弃当前输入仅关闭此编辑，不删除另一个会话的草稿；通过串行 ReleaseEdit 释放匹配会话 binding 并刷新恢复索引，不能释放后续新会话。恢复入口身份已变化也刷新索引，坏密文仍保留独立错误。UI 路由 generation、编辑 session 与 IO 串行队列联合拒绝旧输入/保存/丢弃回调。

坏密文、错 key、未知文件、未确认的密文 partial 均保留，不自动删除或选作恢复来源；恢复数据不进入日志、Bundle、SavedStateHandle 或 capture_draft。索引单草稿损坏隔离由后续 [D02_EDIT_INDEX_ISOLATION.md](D02_EDIT_INDEX_ISOLATION.md) 实现：健康草稿仍可恢复，失败数量明确提示，全局目录/IO故障有独立重试并禁用未确认入口，不阻止读取既有正式原文/此刻草稿。本文件以下109/78数量是该恢复切片的历史范围。只能承诺恢复已确认写入的快照，进行中的写入明确显示待确认。

## 2026-10-13：主动保留编辑草稿并返回

编辑页新增“保留草稿并返回原文”。有修改且本机存储可用时，可先退出编辑，再从列表恢复该草稿，或编辑另一条记录；保留不会生成正式原文版本，也不消费此刻草稿。取消编辑仍沿用明确丢弃确认。

保留命令与自动保存共用队列，先处理已接受的最后一次输入及丢失的写入确认，再以完整绑定快照执行幂等目录持久性确认和完整读回。确认完成后才关闭编辑，草稿保持 ACTIVE。忙碌期间阻止输入、提交、丢弃和重复保留；关闭会话的迟到回调不能改动恢复后的新会话。竞争身份拒绝覆盖；源不可用不重建记录。确认失败保留完整输入和编辑页，明确提示尚未确认及退出风险，可重试保留。

实际新增四项生产控制器/加密文件 JVM 测试：保留 A 后编辑并保留 B、适配器重开恢复 A、只追加一个正式版本；最后一次输入排队与忙碌/旧会话回调；rename 前失败、发布确认丢失、再次持久性确认失败及读回失败；竞争身份及源移除。新增两项真实 Compose App/控制器/加密文件交互，320×640dp、fontScale=2：保留、返回列表、恢复、正式保存，以及确认失败留在编辑并重试。正式记录 IO 仍为显式合成 fixture。
