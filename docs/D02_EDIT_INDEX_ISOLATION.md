# D02 编辑草稿索引损坏隔离

本切片承接 `d150e3ed` 的独立加密原文编辑草稿恢复，修复单个坏密文阻断所有健康恢复入口的缺口。保留两份原始方案、工具链、schema、依赖锁、既有回归和设备 OPEN 门槛；不宣告完整 D02 验收。

## 索引与恢复

`OriginalEditDraftStore.pending()` 返回 `OriginalEditDraftIndex`：完整认证并验证格式的 ACTIVE 草稿元数据，以及认证/格式失败数量、读取期间观察到文件身份变化的数量。只有安全元数据进入恢复列表，原文和修改不进入列表索引、错误文本或日志。

每个匹配自有命名规则的密文独立认证；单个坏 tag、坏格式或被观察到的读取期间替换只隔离该候选，其他健康草稿仍可恢复。坏密文与未知文件原样保留，不自动删除、修复、重写、采用 partial 或尝试替代 key。全部草稿使用错误 key 时返回明确非零失败数量，UI 仍显示错误，不能表示为“没有草稿”。认证失败无法区分损坏与密钥不匹配，提示如实列出可能原因。

目录列举使用可失败的 `DirectoryStream`，不再把 `listFiles()==null` 转成空列表。目录、迭代器、文件读 IO、provider 故障与自有锁 busy 均传播为本次全局索引失败，不降格为单文件损坏。对文件读 IO 与密文内存解析错误分开捕获；只认证/格式失败和明确观察到的单文件身份变化可被逐项隔离。扫描前后核目录身份；目录替换、不可读、列举失败时不返回半份索引。

密文读取有总字节上限；认证成功后再次比较文件类型、fileKey、大小、修改及创建时间，观察到替换/变化则不返回该快照。此检查是乐观读取验证，不声称解决任意恶意文件系统、真实断电或 Android fsync 问题。正常写入继续使用既有同目录 atomic rename、自有非阻塞锁、完整快照 CAS 和幂等持久确认。恢复入口重新验证草稿身份、源记录和不可变源版本；旧恢复索引、已撤销/删除/变化来源与迟到写入不会覆盖新身份或正式原文。

## 实际 UI

恢复列表同时显示健康入口和“X 份编辑草稿无法读取”安全摘要。无私文、文件路径、源 ID、exception 文本或 key 进入错误提示。用户可恢复已认证草稿并独立处理修改；来源已不可用仍展示被恢复的输入并阻止正式提交。错误 key 全部认证失败时，恢复按钮为零但错误仍明确可见，并说明当前没有可安全恢复的编辑草稿、保留数据并重试，不指向不存在的健康入口。正式原文/此刻草稿不会因此被替换。

全局索引失败有独立“重试读取”提示，保留已有加密数据和先前列表元数据，但禁用未重新确认的恢复按钮，ViewModel 也拒绝此时的恢复回调。成功重新读取后恢复健康入口，剩余坏密文仍保持计数错误。既有默认预览状态保持不变；没有为本功能新增 Preview 状态图，380 原预览守卫继续保留。

## 验证与限制

保留全部109项主机回归，新增10项生产 Cipher/文件索引及真实 ViewModel 用例，合计119：两健康一损坏冷索引、多个损坏与错误 key、实际目录/列举失败、文件 IO 故障分类、真实锁与迟到 CAS、保持 mtime 的读取期间替换、健康与源不可用恢复、错误 key 控制器提示、全局刷新失败禁用与重试、恢复期间替换拒绝旧输入。正式 DB 为明确合成 IO；故障钩子注入不冒称真实设备权限或断电故障。
